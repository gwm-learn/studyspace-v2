# 测试方法

> 解决什么问题：用可复现的方法证明"功能对、性能达标、稳定"，而不是"我试了一下能用"。
> 不解决：具体产品测试用例（见 `11.应用与案例/3.测试与认证`）。

## 1. 测试分层

| 层 | 目标 | 例子 |
|---|---|---|
| 单元 | 函数/模块正确 | 解析、校验、状态机 |
| 集成 | 模块间协作 | netifd + proto + 脚本 |
| 系统 | 整机功能 | 拨号、NAT、WiFi、VPN |
| 性能 | 吞吐/时延/并发 | iperf3、PPS、连接数 |
| 稳定 | 长时间/异常 | 72h、反复上下电 |
| 兼容 | 终端/运营商/对端 | 多终端、多 ACS |

## 2. 功能测试

- 每条用例：前置条件 → 步骤 → 预期 → 实际 → 判定。
- 必须覆盖异常路径：断网、超时、认证失败、磁盘满、配置错。
- 回归集：每次改动必跑的核心用例。

## 3. 性能测试

### 3.1 吞吐

```bash
# 服务端
iperf3 -s

# TCP 上行/下行
iperf3 -c 192.0.2.10 -t 30 -P 4
iperf3 -c 192.0.2.10 -t 30 -P 4 -R

# UDP（看丢包/抖动）
iperf3 -c 192.0.2.10 -u -b 500M -t 30
```

矩阵：大包/小包、单流/多流、TCP/UDP、IPv4/IPv6、NAT/非 NAT、开/关加速。

### 3.2 时延/抖动/丢包

```bash
ping -i 0.01 -c 1000 192.0.2.1
mtr -rw 192.0.2.1
```

### 3.3 并发与新建

```bash
# 连接数/新建（工具按需）
wrk -t4 -c1000 -d30s http://192.0.2.1/
ab -n 10000 -c 500 http://192.0.2.1/
```

### 3.4 PPS / 小包

用专业工具（如 TRex/IxChariot）或 `iperf3 -l 64` 近似；注意网卡/驱动限制。

## 4. 稳定性

| 项 | 方法 | 判据 |
|---|---|---|
| 长时间 | 72 h 持续流量 + 周期业务 | 无重启/内存泄漏 |
| 反复上下电 | 50–100 次 | 每次正常启动 |
| 高温 | 烘箱/满载 | 不降速/不死机 |
| 弱网 | tc netem 丢包/延迟/抖动 | 业务可恢复 |
| 异常恢复 | 拔网线/断上游/断电 | 自动重连 |

```bash
# 弱网模拟
tc qdisc add dev eth0 root netem delay 100ms loss 1% reorder 0.5%
```

## 5. 测试报告模板

| 项 | 内容 |
|---|---|
| 版本 | 固件/内核/驱动 commit |
| 拓扑 | 图 + 设备型号 |
| 用例 | 编号、步骤、预期 |
| 结果 | 通过/失败/阻塞 |
| 数据 | 吞吐/时延/丢包/CPU/温度 |
| 结论 | 是否达标，差异原因 |

## 6. 常见错误

| 错误 | 后果 |
|---|---|
| 不记录版本 | 结果不可复现 |
| 只用大包 | 掩盖小包性能问题 |
| 单流测吞吐 | 掩盖多核/多队列问题 |
| 开着抓包测性能 | 数据失真 |
| 忽略温度/功耗 | 实验室过、现场不过 |
| 不测异常路径 | 现网一断就崩 |
