# 自动化测试

> 解决什么问题：把“人肉回归”变成可重复、可门禁、可追溯的流程。
> 不解决：具体产品用例设计（见 [测试方法](01-测试方法.md)）。

## 1. 分层

| 层 | 工具 | 运行环境 |
|---|---|---|
| 单元 | gtest/Unity/CUnit/pytest | 主机 |
| 接口 | pytest/requests | 主机/容器 |
| 设备 | pytest + SSH/serial | 板卡 |
| 系统 | Robot Framework | 板卡/仪表 |
| 性能 | iperf3/trex | 板卡 |
| 镜像 | CI + QEMU/板卡农场 | 虚拟/真实 |

## 2. 最小闭环

```text
拉代码 → 编译 → 烧录/启动 → 健康检查 → 核心用例 → 报告 → 归档
```

每一步失败都要保留现场：日志、抓包、截图、版本。

## 3. 用例设计

- 正常/边界/异常/恢复。
- 前置条件、步骤、预期、清理。
- 幂等/可重跑；避免依赖顺序。
- 失败可定位：断言信息带上下文。

```python
def test_wan_up(dut):
    dut.reboot()
    assert dut.wait_link("wan", timeout=60)
    assert dut.ping("8.8.8.8", count=3)
```

## 4. 设备接入

| 方式 | 用途 |
|---|---|
| SSH | 命令/配置 |
| 串口 | 启动/救砖/无网 |
| Telnet | 老设备（不推荐） |
| API/ubus | 状态/配置 |
| 电源开关 | 上下电测试 |
| 继电器 | 拔线/按键 |

## 5. CI 门禁

| 阶段 | 内容 |
|---|---|
| 提交 | lint/编译/单测 |
| 合并 | 冒烟（启动/网络/升级） |
| 发布 | 全量回归/性能/稳定 |

失败阻断合并；flaky 用例要隔离/修复，不要无限重跑。

## 6. 报告

- 通过/失败/跳过。
- 失败日志/抓包/截图。
- 版本/环境/耗时。
- 趋势（失败率/flaky）。

## 7. 常见问题

| 问题 | 对策 |
|---|---|
| flaky | 隔离/加等待/查竞态 |
| 环境不一致 | 容器/固定版本 |
| 用例慢 | 并行/分层 |
| 失败无现场 | 保留日志/抓包 |
| 只测正常路径 | 加异常/恢复 |

## 8. 安全

- 测试凭证不入库。
- 测试网络隔离。
- 自动化脚本最小权限。
- 日志脱敏。
