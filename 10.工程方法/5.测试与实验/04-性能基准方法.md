# 性能基准方法

> 解决什么问题：数字可比、可复现、能解释瓶颈；不被“环境差异/测试方法”骗。
> 不解决：具体产品指标（按合同/需求）。

## 1. 必记字段

| 字段 | 示例 |
|---|---|
| 固件/内核 | commit/版本 |
| 硬件 | 型号/内存/Flash |
| 拓扑 | 图/线缆/仪表 |
| 工具/参数 | `iperf3 -P4 -t30` |
| 温度/功耗 | ℃/W |
| 加速/QoS | on/off |

## 2. 指标

| 指标 | 说明 |
|---|---|
| 吞吐 | Mbps/Gbps |
| PPS | 小包能力 |
| 时延/抖动 | 空载/满载 |
| 丢包 | 队列/链路 |
| 新建/并发 | 连接数 |
| CPU/软中断 | 瓶颈 |
| 温度/功耗 | 可持续性 |

## 3. 测试矩阵

| 维度 | 取值 |
|---|---|
| 包长 | 64/128/512/1518 |
| 流数 | 1/4/多 |
| 协议 | TCP/UDP、IPv4/IPv6 |
| 路径 | NAT/非 NAT、PPPoE |
| 功能 | 开/关加速、QoS、VLAN |
| 方向 | 上/下行/双向 |

## 4. 工具

```bash
iperf3 -s
iperf3 -c 192.0.2.10 -t 30 -P 4
iperf3 -c 192.0.2.10 -t 30 -P 4 -R
iperf3 -c 192.0.2.10 -u -b 500M -t 30
ping -i 0.01 -c 1000 192.0.2.1
mpstat -P ALL 1
cat /proc/softirqs
```

小包/PPS 用专业仪表（TRex/IxChariot）或 `iperf3 -l 64` 近似。

## 5. 方法

1. 基线：默认配置，空载。
2. 变量：一次只改一个（加速/QoS/包长）。
3. 重复：至少 3 次，取中位数。
4. 记录：版本/温度/CPU/丢包。
5. 对比：同环境前后对比。

## 6. 统计

- 吞吐取稳定段，去掉启动/结束瞬态。
- 时延取 P50/P95/P99，不只看平均。
- 丢包/抖动要区分空载/满载。
- 异常点复测/保留抓包。

## 7. 报告

```text
目标/版本/拓扑
测试矩阵
结果表（吞吐/PPS/时延/CPU/温度）
瓶颈分析
结论/建议
附录：原始数据/抓包
```

## 8. 常见错误

| 错误 | 后果 |
|---|---|
| 不记版本 | 不可复现 |
| 只测大包 | 掩盖小包问题 |
| 单流 | 掩盖多核/多队列 |
| 开抓包测性能 | 数据失真 |
| 忽略温度 | 实验室过/现场不过 |
| 只测空载时延 | 掩盖 bufferbloat |
