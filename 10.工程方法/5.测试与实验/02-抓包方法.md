# 抓包方法

> 解决什么问题：在正确的位置、用正确的过滤器，抓到能证明结论的包。
> 不解决：具体协议的字段解释（见各协议卡）。

## 1. 先想清楚三个问题

1. **抓哪里**：终端、AP、网桥、WAN、上游、内核？
2. **抓什么**：五元组、协议、VLAN、PPPoE、无线管理帧？
3. **证明什么**：丢在哪一跳、谁没回、字段对不对？

## 2. 抓包点

```text
终端 ── AP/交换机 ── 网桥 ── 路由/NAT ── WAN ── 上游
  ▲        ▲           ▲          ▲         ▲
  │        │           │          │         │
终端抓   空口抓        br-lan     wan      上游/镜像
```

| 位置 | 能看到 | 看不到 |
|---|---|---|
| 终端 | 本机收发 | 中间丢包 |
| AP 空口 | 管理/数据帧、重传 | 有线侧 |
| br-lan | 二层转发 | NAT 后 |
| wan | NAT 后、拨号 | 内网原始地址 |
| 上游 | 运营商侧 | 设备内部 |

**关键**：NAT 前后地址不同，必须对照抓。

## 3. 常用命令

```bash
# 基础
tcpdump -ni any -s0 -w cap.pcap
tcpdump -ni eth0 host 192.0.2.1 and port 80

# PPPoE
tcpdump -ni wan -s0 'pppoe or pppoes'

# VLAN
tcpdump -ni eth0 -e -s0 'vlan 100'

# ICMPv6 / DHCPv6
tcpdump -ni any 'icmp6 or udp port 546 or udp port 547'

# 无线管理帧（monitor 接口）
tcpdump -ni mon0 -e -s0 'wlan type mgt'

# 环形缓冲（长时间）
tcpdump -ni any -s0 -C 100 -W 20 -w cap.pcap
```

## 4. Wireshark/tshark

```bash
# 统计
tshark -r cap.pcap -q -z io,stat,1
tshark -r cap.pcap -q -z conv,tcp

# 过滤
tshark -r cap.pcap -Y 'tcp.analysis.retransmission'
tshark -r cap.pcap -Y 'dns.flags.rcode != 0'

# 导出字段
tshark -r cap.pcap -T fields -e frame.time -e ip.src -e ip.dst -e tcp.flags
```

常用显示过滤器：

| 目的 | 过滤器 |
|---|---|
| 重传 | `tcp.analysis.retransmission` |
| 零窗口 | `tcp.analysis.zero_window` |
| RST | `tcp.flags.reset == 1` |
| DNS 失败 | `dns.flags.rcode != 0` |
| ARP 冲突 | `arp.duplicate-address-detected` |
| DHCP 失败 | `dhcp.option.dhcp == 3`（请求无响应需对照） |

## 5. 分析流程

1. **时间线**：先看谁先发、谁没回。
2. **五元组**：确认地址/端口/NAT 转换。
3. **状态**：SYN→SYN/ACK→ACK、FIN/RST。
4. **重传/乱序/零窗口**：判断丢包/拥塞。
5. **载荷**：协议字段是否符合预期。
6. **对照**：两端抓包对比，定位丢在哪一跳。

## 6. 常见陷阱

| 陷阱 | 说明 |
|---|---|
| 抓包点不对 | NAT 后看不到内网地址 |
| 快照长度太小 | 截断载荷，协议解析失败 |
| 硬件 offload | 后续包不走协议栈，抓不到 |
| 时间不同步 | 多设备抓包无法对齐 |
| 过滤器太宽 | 丢包/性能失真 |
| 无线抓包 | 需要 monitor 模式与正确信道 |
