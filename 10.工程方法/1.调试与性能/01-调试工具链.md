# 调试工具链

> 解决什么问题：程序崩溃、卡死、性能差、内存涨，怎么用工具拿到证据。
> 不解决：具体业务逻辑。

## 1. 选工具

| 现象 | 首选 | 备选 |
|---|---|---|
| 崩溃/段错误 | coredump + gdb | ASan |
| 卡死/死锁 | gdb attach + 线程栈 | strace |
| 系统调用失败 | strace | ltrace |
| CPU 高 | perf top/record | ftrace |
| 内核延迟/调用链 | ftrace | bpftrace |
| 内存泄漏 | valgrind / ASan | heaptrack |
| 竞态 | ThreadSanitizer | 日志 |

## 2. coredump + gdb

```bash
ulimit -c unlimited
cat /proc/sys/kernel/core_pattern
# 复现后
gdb ./prog core
(gdb) bt full
(gdb) thread apply all bt
(gdb) info registers
```

嵌入式设备：确认 `core_pattern` 指向可写路径；空间不足时用 `coredumpctl` 或只保留栈。

## 3. strace

```bash
strace -f -tt -T -s 256 -o trace.log ./prog
strace -f -e trace=network,openat ./prog
strace -p <pid>
```

看：返回值（`-1 EACCES`）、耗时（`<...>`）、调用顺序。

## 4. perf

```bash
perf top
perf record -g -p <pid> -- sleep 30
perf report
perf stat -e cycles,instructions,cache-misses ./prog
```

嵌入式需内核开启 `CONFIG_PERF_EVENTS`；符号缺失时用 `-k`/vmlinux。

## 5. ftrace

```bash
cd /sys/kernel/debug/tracing
echo function > current_tracer
echo 1 > tracing_on
cat trace
echo 0 > tracing_on
```

常用：

```bash
# 函数图
echo function_graph > current_tracer
# 过滤
echo 'ip_rcv' > set_ftrace_filter
# 事件
echo 1 > events/net/enable
```

## 6. 内存与并发

```bash
valgrind --leak-check=full ./prog
gcc -fsanitize=address,undefined -g ./prog.c
gcc -fsanitize=thread -g ./prog.c
```

注意：ASan/TSan 会改变时序与内存占用，嵌入式上可能跑不动，需交叉编译。

## 7. 日志与断点

- 日志：分级、带时间/线程/模块；避免在热路径打印。
- 断点：`gdb` 远程 `target remote :1234`（kgdb/JTAG）。
- 内核：`dynamic_debug`、`printk` 级别、`pstore`。

## 8. 排查顺序

```text
能复现？ → 不能：加日志/断言/压力
   │
   ▼
崩溃？ → coredump/gdb
   │
   ├─ 卡死 → 线程栈/strace
   ├─ 性能 → perf/ftrace
   └─ 内存 → valgrind/ASan
```
