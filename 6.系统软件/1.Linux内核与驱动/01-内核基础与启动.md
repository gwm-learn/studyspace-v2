# 内核基础与启动


## Linux011启动流程


Linux 0.11 的启动过程可以分为三个阶段：BIOS引导（实模式）、setup准备（实模式到保护模式过渡）、head初始化（保护模式+分页）。源码位于 `Linux011/boot/`（bootsect.s、setup.s、head.s）和 `Linux011/init/main.c`。

### 启动总览

| 阶段 | 入口 | 运行模式 | 主要工作 |
| :--- | :--- | :--- | :--- |
| 引导 | bootsect.s | 实模式 | 加载setup和system到内存 |
| 过渡 | setup.s | 实模式 | 取硬件参数，开启A20和PE，跳入保护模式 |
| 内核初始化 | head.s | 保护模式 | 建IDT/GDT、开分页，调用main |
| 主函数 | main.c | 保护模式+分页 | 初始化各子系统，创建进程1 |

整个内核镜像在磁盘上的布局是：bootsect（1个扇区，512字节）、setup（4个扇区）、system（head.s+内核代码+数据），三者依次存放。

### bootsect.s 引导扇区

BIOS把第一个扇区读到物理地址 0x7C00，然后跳转执行，这就是bootsect.s。

1. 把自身从 0x7C00 搬到 0x90000，腾出低端内存。
2. 用 INT 13 读取磁盘：setup.s 读到 0x90200，system 读到 0x10000。
3. 读取磁盘参数表（每磁道扇区数、磁头数），保存到 CS:0x90000 附近，供 setup 使用。
4. 跳转到 0x90200 执行 setup.s。

bootsect.s 由 BIOS 加载并执行，因此不能依赖任何操作系统服务，全部用 BIOS 中断 INT 13/INT 10 完成磁盘与屏幕操作。

### setup.s 实模式准备

setup.s 继续在实模式下运行，为进入保护模式做准备。

1. 通过 INT 15 读取内存大小，保存到 0x90002（memory_end）。
2. 读取硬盘参数表 hd0/hd1，保存到 0x90080 开始的 drive_info。
3. 读取显示模式（EGA/VGA），保存到 0x9000E。
4. 把整个 system 从 0x10000 搬运到物理地址 0x00000（内存最低端），因为 head.s 的分页代码假定自己从地址0开始。
5. 加载 IDTR 指向临时 IDT、GDTR 指向 GDT（段描述符表）。
6. 关中断、开启 A20 地址线（向 0x92 端口写 0x02）。
7. 把 CR0 的 PE（保护模式使能）位置1，然后 `jmpi 0,8` 跳转到保护模式下的代码段，进入 head.s。

关键点：实模式地址是 `段<<4+偏移`，只有20位地址线有效；开启A20后内存寻址才能到达1MB以上，这是进入保护模式的必要前提。

### head.s 保护模式初始化

head.s 被链接在 system 的最前面，因此在保护模式下它位于物理地址 0x00000，分页目录也放在这里。

1. 重新加载段寄存器：DS/ES/FS/GS/SS 指向数据段（0x10），CS 已经是代码段（0x08），建立内核栈。
2. 用忽略中断 `ignore_int` 填充整个 IDT（256个中断描述符），避免未初始化中断导致系统崩溃。
3. 检查 A20 是否真的打开（比较1MB处内存），检查数学协处理器是否存在。
4. 设置分页：页目录 `_pg_dir` 在0x0，4个页表 pg0~pg3 从 0x1000 开始，把物理内存前16MB映射为虚拟地址0~16MB（一一映射），页表项加上 present/user/rw 标志。
5. `movl %eax,%cr3` 加载页目录基址，`movl %eax,%cr0`（置PG位）开启分页。
6. 建立与位置无关的跳转，然后 `pushl $L6` 作为返回地址压栈，`call _main` 进入C语言主函数。

head.s 同时定义了 `_gdt`、`_idt`、`_pg_dir`、`_tmp_floppy_area` 等全局符号，供内核其他模块引用。

### 分页初始化细节

Linux 0.11 采用两级页表，页目录项指向页表，页表项指向4KB物理页。head.s 中只建了页表结构，真正的页表内容由 mm/memory.c 在缺页时填充。

| 项 | 位置 | 说明 |
| :--- | :--- | :--- |
| _pg_dir | 0x00000 | 页目录，占1页 |
| pg0 | 0x01000 | 页表0，映射0~4MB |
| pg1 | 0x02000 | 页表1，映射4~8MB |
| pg2 | 0x03000 | 页表2，映射8~12MB |
| pg3 | 0x04000 | 页表3，映射12~16MB |

内核使用 `_pg_dir+7` 这种"页表地址+标志"的写法，把present和rw标志直接编码进页目录项。由于启动时内核映射了前16MB，在 mem_init 把空闲页交给伙伴系统之前，代码和数据可以安全运行。

### main.c 主函数

head.s 通过 call 进入 `main()`，此时系统处于保护模式+分页状态，中断仍处于关闭状态。main 依次初始化各子系统：

| 调用 | 作用 |
| :--- | :--- |
| mem_init | 初始化内存管理，统计可用内存页 |
| trap_init | 设置异常处理（缺页、除法错等） |
| blk_dev_init / chr_dev_init | 块设备和字符设备初始化 |
| tty_init | 终端（串口+控制台）初始化 |
| time_init | 读取CMOS时间，设置系统时钟 |
| sched_init | 初始化进程调度（设置时钟中断） |
| buffer_init | 初始化块设备高速缓冲 |
| hd_init / floppy_init | 硬盘、软盘驱动初始化 |
| sti() | 开中断 |
| move_to_user_mode | 从内核态切换到用户态（进程0） |

### 第一个进程的创建

main 完成初始化后调用 `move_to_user_mode()`，这是利用iret指令的机制：在栈上伪造用户态的CS/EIP/EFLAGS，iret后CPU就回到了用户态特权级0进程。

1. `fork()` 创建进程1（init进程），返回后父子进程分叉。
2. 子进程执行 `init()`：调用 `setup()` 挂载根文件系统，打开/dev/tty0作为标准输入输出，再 `fork()` 出子进程执行 `/bin/sh`。
3. 父进程（进程0）进入 `for(;;) pause()`，永远睡眠等待调度。

### 启动流程时序图

```
BIOS ──→ bootsect.s ──→ setup.s ──→ head.s ──→ main.c
(0x7C00)  (搬到0x90000)  (取参数/开A20)  (保护模式+分页)  (子系统初始化)
                         │
                         └─ 实模式 保护模式 ──→ 分页 ──→ move_to_user_mode ──→ fork(init) ──→ /bin/sh
```

### 关键点总结

1. 实模式只有1MB寻址空间，保护模式通过段选择子+分页获得完整32位寻址。
2. A20地址线是实模式向保护模式过渡的物理前提，不打开就无法访问1MB以上内存。
3. 分页让每个进程拥有独立的虚拟地址空间，是进程隔离的基础。
4. main.c 是内核第一个C函数，但此时还运行在内核态进程0中，直到 move_to_user_mode 才变成用户态。
5. 启动完成后系统运行着进程0（空闲循环）和进程1（init），后续所有进程都由fork产生。

## 2025.3.4
1. 中断   
中断分为中断和异常   
中断是通过外部设备给CPU的INTR引脚发送信号   
异常是CPU自己执行指令的时候发现特殊情况触发的   
还有INT指令，INT指令后面跟一个数字，就相当于直接用指令的形式，告诉CPU一个中断号   
linux一般会把中断分为上下两部分执行，上半部分处理简单的逻辑，将下半部分直接丢给一个软中断异步处理
