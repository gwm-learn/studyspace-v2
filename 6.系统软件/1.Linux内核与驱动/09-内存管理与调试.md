# 内存管理与调试

> 解决什么问题：内核/用户态内存泄漏、越界、OOM、碎片、DMA 一致性。
> 不解决：具体分配器实现（SLUB/SLAB 细节）。

## 1. 地址空间

| 类型 | 说明 |
|---|---|
| 物理地址 | 总线/DRAM |
| 虚拟地址 | MMU 映射 |
| 内核线性映射 | `PAGE_OFFSET` |
| vmalloc 区 | 虚拟连续、物理可不连续 |
| 用户空间 | 每进程独立 |

## 2. 内核分配

| API | 特点 | 场景 |
|---|---|---|
| `kmalloc` | 物理连续、小块 | 一般 |
| `kzalloc` | 清零 | 一般 |
| `vmalloc` | 虚拟连续、大块 | 大缓冲 |
| `alloc_pages` | 页级 | DMA/大页 |
| `devm_*` | 生命周期绑定设备 | 驱动 |
| `kmem_cache` | 对象池 | 高频同尺寸 |

GFP 标志：

- `GFP_KERNEL`：可睡眠，进程上下文。
- `GFP_ATOMIC`：不可睡眠，中断/持锁。
- `GFP_DMA`：DMA 可达区域。
- `__GFP_ZERO`：清零。

## 3. 用户态内存

| API | 说明 |
|---|---|
| `malloc/free` | 堆 |
| `mmap` | 文件/匿名映射 |
| `brk` | 堆扩展 |
| `mlock` | 锁定不换出 |
| `madvise` | 提示内核 |

## 4. DMA

- 一致性 DMA：`dma_alloc_coherent`。
- 流式 DMA：`dma_map_single`/`dma_unmap_single`。
- 注意 cache 一致性/屏障/方向。
- 设备地址 ≠ CPU 物理地址（IOMMU）。

## 5. 泄漏与越界

### 5.1 内核

```bash
cat /proc/meminfo
cat /proc/slabinfo
cat /sys/kernel/debug/kmemleak
echo scan > /sys/kernel/debug/kmemleak
dmesg | grep -i -E 'oom|leak|BUG'
```

- `kmemleak` 需要内核配置。
- KASAN 查越界/use-after-free。
- `slabinfo` 看对象增长。

### 5.2 用户态

```bash
valgrind --leak-check=full ./prog
gcc -fsanitize=address,undefined -g prog.c
heaptrack ./prog
```

## 6. OOM

- 触发：内存耗尽/超额分配。
- 查看：`dmesg` 的 OOM killer 日志、`/proc/<pid>/status`。
- 对策：限制缓存/连接数、修复泄漏、增加 swap（谨慎）、cgroup 限制。

## 7. 碎片

- 频繁分配不同大小 → 外部碎片。
- 对策：对象池、固定大小、`vmalloc`、提前分配。
- 长时间运行设备要关注。

## 8. 常见坑

| 现象 | 原因 |
|---|---|
| 泄漏 | 失败路径未释放 |
| 越界 | 长度未校验 |
| OOM | 大页/递归/缓存 |
| 碎片 | 频繁分配不同大小 |
| 原子上下文睡眠 | `GFP_KERNEL` 用在中断 |
| DMA 数据错 | cache/方向/地址 |

## 9. 检查表

- [ ] 分配/释放成对。
- [ ] 失败路径释放。
- [ ] 长度/索引校验。
- [ ] GFP 标志与上下文匹配。
- [ ] DMA 映射/解映射/屏障。
- [ ] 长时间运行监控内存。
