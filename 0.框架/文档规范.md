# 文档规范

## 零、域归属（先定域，再写）

新增内容先按 [知识框架](知识框架.md) 的 11 个域归类：

| 内容 | 归属 |
|---|---|
| 数学/物理/电子/信号 | `1.基础科学` |
| 语言/算法/数据结构/脚本 | `2.计算机科学` |
| 协议原理/地址/路由/传输/应用 | `3.网络科学` |
| 无线/蜂窝/射频/ODU 空口 | `4.通信科学` |
| 板级/启动/DTS/分区/接口 | `5.嵌入式系统` |
| 内核/驱动/网络栈 | `6.系统软件` |
| OpenWrt/Yocto/构建/集成 | `7.平台与集成` |
| DSA/NAT/QoS/转发加速 | `8.数据面工程` |
| 终端管理/VPN/证书 | `9.管理与安全` |
| 调试/测试/抓包/环境 | `10.工程方法` |
| 项目/认证/产线/运维 | `11.应用与案例` |

**禁止**：把 OpenWrt 当成顶层知识域；把项目周期/学习天数当成目录结构；把厂商型号当成知识域。

## 一、三条铁律

1. **单一归属**：一个知识点只有一个主文件。别处只能链接。
2. **先搜后写**：新建前先全库搜索同义词；已有主文件就补章节，不新建平行文档。
3. **不复制**：跨文档引用一律用相对链接；不得整段搬运。

## 二、目录与命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 目录 | `NN.中文名`，两位序号 | `03.管理平面/` |
| 笔记 | `NN-中文名.md` | `02-netifd源码剖析.md` |
| 入口 | 固定 `00-总览.md` | — |
| 图片 | 同级 `assets/`，`fig-NN-描述.png` | `assets/fig-01-收包路径.png` |
| 图源 | `.drawio` 与导出 `.png` 同放 `assets/` | — |
| 禁止 | `&`、空格、`（）`、`readme`/`README` 混用、`m-` 前缀 | — |

新增目录必须同时：
1. 建 `00-总览.md`；
2. 在上级 Hub 登记；
3. 更新 [知识框架图.md](知识框架图.md) 与上级 Hub。

## 三、元数据（frontmatter）

```yaml
---
id: "net-04"              # 全库唯一、稳定；改名不改 id
title: "ARP 与邻居发现"
cluster: net              # 主题簇代码，见知识框架
layer: L2                 # L1 概念 / L2 实现 / L3 实操 / L4 产品
status: draft             # draft / review / verified / deprecated
confidence: medium        # high 实测或源码 / medium 多源 / low 推断
platform: ["OpenWrt 23.05", "kernel 5.15"]
source:
  - type: rfc
    ref: "RFC 826"
  - type: code
    ref: "net/ipv4/arp.c"
verified_on: 2026-10-24
tags: ["arp", "ipv4"]
aliases: ["ARP"]
created: 2026-10-24
updated: 2026-10-24
---
```

规则：
- `layer` 为 L2/L3/L4 时，`platform` 不得为空。
- `status: verified` 必须有 `verified_on` 和可核对来源。
- `confidence: low` 的结论不得被其他笔记当作前提引用。

## 四、分层写法

| 层 | 必须写 | 禁止写 |
|---|---|---|
| L1 | 定义、模型、边界、常见误解、图 | 配置步骤、长代码 |
| L2 | 版本、入口、调用链、关键结构、关键代码、验证方法 | 重抄 L1 定义 |
| L3 | 环境、拓扑、步骤、预期输出、失败排查 | 重抄 L1/L2 |
| L4 | 场景、决策、流程、检查表、案例 | 重抄技术原理 |

## 四之二、内容深度标准（防止“提纲式笔记”）

> 目的：避免“要点式”笔记导致读者无法据此实现/排障。以下是最低深度要求。

| 层 | 最低行数 | 必须包含 |
|---|---:|---|
| L1 概念 | 80 | 背景/边界、模型/公式、工程含义、常见误区、相关 |
| L2 实现 | 100（建议 120+） | 原理、机制/流程、关键结构/代码、配置/命令、验证、故障模式、取舍 |
| L3 实操 | 90（建议 100+） | 环境、步骤、预期、判据、失败排查、清理/复现 |
| L4 应用 | 80 | 场景/约束、选项/决策、流程、证据、复盘/预防 |

**禁止**：

- 只有 3–5 条 bullet、没有机制/证据的“提纲”。
- 用“待补”代替正文；确实缺数据时，写清“缺什么/怎么补/影响什么”。
- 只贴命令不解释判据；只贴结论不写来源。
- 把同一段内容复制到多篇。

**推荐结构**（可按类型裁剪）：

1. 问题与边界
2. 核心概念/模型（图/公式/表）
3. 工作机制/流程（步骤/时序）
4. 工程实现/配置（代码/命令/参数）
5. 验证与实验（环境/步骤/预期/判据）
6. 故障模式与排查（表）
7. 设计取舍/经验
8. 参考资料
9. 相关

## 五、完成标准（DoD）

- [ ] frontmatter 完整合法；
- [ ] H1 与 `title` 一致；
- [ ] 开头 3 行内说明"本文解决什么问题/不解决什么"；
- [ ] 有前置知识链接与相关主题链接（≥2 条）；
- [ ] 关键结论有来源（≥1 条可核对）；
- [ ] L2 以上有图/表，L3 有可复现命令与预期输出；
- [ ] L2 以上有失败模式或排查；
- [ ] 无整段复制；
- [ ] 已挂到 Hub；
- [ ] `python3 tools/kb_lint.py` 通过。

## 六、链接与图片

- 只用相对链接；禁止绝对路径、`file://`、外部图床。
- 链接到目录时指向该目录的 `00-总览.md`。
- 图片必须落在 `assets/` 并被正文引用；drawio 必须导出 png 并引用 png。
- 重命名/移动后运行 `tools/fix_links.py` 重写链接，断链为 0 才提交。

## 七、合并规则

1. 先冻结该主题，登记到 [维护台账.md](%E7%BB%B4%E6%8A%A4%E5%8F%B0%E8%B4%A6.md)。
2. 逐节比对：独有 / 重复 / 冲突。
3. 选主：主归属域 + 内容最全 + 有来源。
4. 合并独有内容；冲突处并列来源与版本。
5. 移动后在原位置留 stub 或归档。
6. 更新所有入链。
7. 跑 lint + 抽读。

## 八、AI 协作规则

- 一次只做一个工单，工单必须写明"允许改动路径"。
- 不得编造函数名/行号/RFC 条款；不确定写"待核实"。
- 不得删除未归档内容；不得修改 `99-归档/`。
- 不得新建与既有主文件平行的同主题文档。
- 生成内容默认 `status: draft`、`confidence: low`，核对后才能升级。
- 提交信息：`kb(<批次>): <动作>`。

## 九、提交前检查

```bash
python3 tools/kb_lint.py
python3 tools/kb_dup.py
python3 tools/kb_stats.py
```

三项全绿才算完成。
