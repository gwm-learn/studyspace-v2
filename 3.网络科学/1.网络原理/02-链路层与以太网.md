### 成帧与 MAC/LLC 子层

IEEE 802 标准把数据链路层分为两个子层：

| 子层 | 作用 |
|------|------|
| MAC（媒体接入控制） | 帧的封装与解封装、介质访问控制（CSMA/CD）、MAC 地址寻址、差错检测（FCS） |
| LLC（逻辑链路控制） | 对上提供统一接口，承载网络层协议（IP、IPX 等），通过 LLC 头区分上层协议 |

以太网帧由 MAC 子层完成封装：前导码 + 目的 MAC + 源 MAC + 长度/类型 + 数据 + FCS。LLC 子层位于 MAC 之上，802.2 定义的 LLC 头含 DSAP/SSAP/Control 字段。现代以太网多用"类型字段"直接标识上层协议（如 0x0800 表示 IPv4），LLC 主要用于 802.3 无类型帧（如 STP、PPPoE 的封装识别）。

### 链路层在何处实现
典型的主机体系结构：链路层的主题部分是在网络适配器中实现的，网络适配器有时也称为网络接口卡NIC。位于网络适配器核心的是链路层控制器，该控制器通常是一个实现了许多链路层服务的专用芯片。链路层控制器的许多功能是用硬件实现的。

### 以太网与 CSMA/CD

经典以太网使用 CSMA/CD（载波侦听多路访问/碰撞检测）作为随机接入协议：

1. **载波侦听**：发送前先监听信道，空闲才发送，避免"先发后撞"。
2. **碰撞检测**：边发边听，发现信号冲突立即停止发送。
3. **强化碰撞**：发送方补发 32 位拥塞信号，让所有站点都能感知碰撞。
4. **指数退避**：碰撞后随机退避（k 次碰撞后在 0~2^k-1 倍时隙中随机等待），降低再次碰撞概率。

限制：CSMA/CD 依赖边发边听，要求**最小帧长**（以太网 64 字节），保证发送方在发完前能检测到最远端的碰撞。因此设计有距离上限（10Mb/s 时 2500m）。现代全双工交换网络不存在共享介质，链路点对点连接，CSMA/CD 已无用武之地。

## 链路层寻址
### MAC地址
事实上，并不是主机或路由器具有链路层地址，而是它们的适配器（即网络接口）具有链路层地址。   
MAC地址的一个有趣性质是没有两块适配器具有相同的地址。适配器的MAC地址具有扁平结构，而且不论适配器到哪里都不会变化。   

### ARP 地址解析协议
ARP，将网络层地址和链路层地址之间进行转换。   
两种情况：   
子网内发送数据报前使用ARP，主机A向主机B发送ARP查询分组获取主机B的MAC地址   
发送数据报到另一个子网前使用ARP，主机A向路由器C发送ARP查询分组获取路由器C的MAC地址，数据报发送到路由器C之后，路由器C向主机B发送ARP查询分组获取主机B的MAC地址   

## 链路层交换机
接收入链路层并将它们转发到出链路。   

### 交换机转发和过滤
过滤（filtering）是决定一个帧应该转发到某个接口还是应当将其丢弃的交换机功能。 转发（forwarding）是决定一个帧应该被导向哪个接口，并把该帧移动到那些接口的交换 机功能。   

#### 交换机自学习

交换机维护一张 **MAC 地址表（CAM 表）**，表项为 {MAC 地址, 接口, 老化时间}，通过**自学习**填充：

1. 收到帧时记录"源 MAC → 入接口"映射，并刷新该表项的老化时间（默认 300s）。
2. 转发时查表：目的 MAC 在表中且接口不同 → 只往该接口转发。
3. 目的 MAC 不在表中 → 向除入接口外的所有接口**泛洪**。
4. 目的 MAC 对应的接口与入接口相同 → 过滤丢弃。

#### 交换机转发场景

| 场景 | 处理 |
|------|------|
| 目的 MAC 已知且非入接口 | 单播转发 |
| 目的 MAC 未知 | 泛洪（广播域内广播） |
| 目的 MAC 与源同接口 | 丢弃（过滤） |
| 广播/组播帧 | 泛洪 |
| 环路存在 | 需 STP 协议阻断，否则广播风暴 |

交换机的三大特性：**即插即用**（无需配置）、**自学习转发表**、**隔离冲突域**（每个端口独享带宽）。注意交换机不隔离广播域，广播帧会泛洪到所有端口，VLAN 才是隔离广播域的手段。

## 链路层协议详解（Data Link Layer）


### 1. 概述：链路层在 TCP/IP 协议栈中的角色

链路层（Link Layer）位于协议栈的最底层，紧贴物理层之上。它的核心职责是把上层网络层的 IP 数据报封装成**帧（Frame）**，并在相邻节点（同一链路上）之间完成传输。

| 层次 | TCP/IP 模型 | OSI 模型 | 典型协议/设备 |
|------|-------------|----------|---------------|
| 第 4 层 | 应用层 | 应用层 / 表示层 / 会话层 | HTTP、DNS、DHCP |
| 第 3 层 | 网络层（网际层） | 网络层 | IP、ICMP、ARP、路由协议 |
| 第 2 层 | 链路层（网络接口层） | 数据链路层 | Ethernet、PPP、802.11、网桥/交换机 |
| 第 1 层 | — | 物理层 | 双绞线、光纤、网卡 |

关键理解点：

- TCP/IP 模型中链路层负责的功能在 OSI 模型中被拆成**数据链路层**和**物理层**两层，因此链路层文档中常同时涉及帧格式（L2）与电气/信号特性（L1）。
- 帧是链路层的传输单元，IP 包是网络层的传输单元。**IP 地址负责跨网络寻址（端到端），MAC 地址负责同链路内寻址（一跳一跳）**，两者职责互补。
- 常见链路层协议：以太网（Ethernet）、PPP、PPPoE、IEEE 802.11（Wi-Fi）、HDLC 等。本笔记以以太网为主线。

### 2. 以太网帧结构（Ethernet II）

以太网使用最广泛的帧格式是 **Ethernet II**（也称 DIX 帧，由 DEC、Intel、Xerox 三家联合定义）。完整帧结构如下：

| 字段 | 长度 | 内容说明 |
|------|------|----------|
| 前导码（Preamble） | 7 字节 | 连续 `10101010`，用于接收方同步时钟 |
| 帧起始符（SFD） | 1 字节 | `10101011`，标志数据帧开始 |
| 目的 MAC（DA） | 6 字节 | 帧的接收方 MAC 地址 |
| 源 MAC（SA） | 6 字节 | 帧的发送方 MAC 地址 |
| EtherType（类型） | 2 字节 | 标识上层协议类型，如 `0x0800` 表示 IPv4 |
| 载荷（Payload） | 46 ~ 1500 字节 | 上层 IP 数据报，不足 46 字节需填充（Padding） |
| FCS（帧校验序列） | 4 字节 | CRC-32 校验值，覆盖 DA 到 Payload 全部字段 |

关于帧长度的两个关键数字：

- **最小帧长 64 字节**（前导码与 SFD 不计入）：`14 字节头 + 46 字节最小载荷 + 4 字节 FCS`。这一限制源于半双工 CSMA/CD 的冲突检测需求，发送方必须保证帧在冲突信号返回前仍在发送。
- **最大帧长 1518 字节**：`14 字节头 + 1500 字节最大载荷 + 4 字节 FCS`。载荷上限 1500 字节就是经典的 **MTU = 1500** 来源。

> FCS 使用 CRC-32 校验，接收方计算不匹配时直接丢弃该帧。注意：以太网 FCS 只保证**一跳内**传输无差错，跨路由的完整性由上层协议（如 TCP 校验和）保证。

### 3. MAC 地址

#### 3.1 MAC 地址格式

MAC 地址共 48 位（6 字节），用十六进制表示，如 `00:1A:2B:3C:4D:5E`。

| 字节范围 | 名称 | 分配者 | 含义 |
|----------|------|--------|------|
| 前 3 字节 | OUI（组织唯一标识符） | IEEE 统一分配 | 标识网卡厂商，如 `00:1A:2B` 属于某厂商 |
| 后 3 字节 | 网卡接口标识 | 厂商自行分配 | 同一厂商内唯一标识某块网卡 |

#### 3.2 MAC 地址的分类（首字节低两位）

MAC 地址的首字节最低位和次低位具有特殊含义：

| 位 | 名称 | 值 | 含义 |
|----|------|----|------|
| 第 0 位 | I/G 位（Individual/Group） | 0 | **单播（Unicast）**，唯一标识一块网卡 |
| 第 0 位 | I/G 位 | 1 | **组播（Multicast）**，标识一组接收者 |
| 第 1 位 | U/L 位（Universal/Local） | 0 | **全局唯一**，由 IEEE 分配 |
| 第 1 位 | U/L 位 | 1 | **本地管理**，管理员自行定义，如虚拟化网卡 |

#### 3.3 特殊 MAC 地址

| MAC 地址 | 类型 | 用途 |
|----------|------|------|
| `FF-FF-FF-FF-FF-FF` | 广播 | 发给链路上所有节点，IPv4 ARP 请求即用此地址 |
| `01-00-5E-XX-XX-XX` | 组播 | IPv4 组播地址映射到以太网组播 MAC 的固定前缀 |
| `33-33-XX-XX-XX-XX` | 组播 | IPv6 组播（如 `FF02::1` 全节点）映射的以太网前缀 |
| `01-80-C2-00-00-00` | 组播 | 桥接协议（如 STP）使用的保留地址，交换机不转发 |

> 广播地址本质上是"所有位全 1"的组播地址，两者共用一个 I/G 位分类。

### 4. 以太网帧的封装类型

#### 4.1 Ethernet II 与 IEEE 802.3

两种帧格式通过**第 13、14 字节**区分：该字段是 Type（类型）还是 Length（长度）。

| 帧格式 | 第 13/14 字节 | 判别方法 | 上层 |
|--------|---------------|----------|------|
| Ethernet II | EtherType | 值 >= `0x0600`（1536） | 直接封装 IP 等网络层协议 |
| IEEE 802.3 | Length | 值 <= 1500 | 需配合 LLC/SNAP 再标识上层协议 |

由于 Type 值最小从 `0x0600` 起、Length 最大到 1500（`0x05DC`），两者数值区间不重叠，接收方据此判别。现代网络几乎全部使用 Ethernet II。

常用 EtherType 值：

| 值 | 协议 |
|----|------|
| `0x0800` | IPv4 |
| `0x0806` | ARP |
| `0x86DD` | IPv6 |
| `0x8100` | VLAN 标签（802.1Q） |
| `0x8863` / `0x8864` | PPPoE Discovery / PPPoE Session |
| `0x88CC` | LLDP |

#### 4.2 802.1Q VLAN 标签

VLAN 标签在 Ethernet II 的源 MAC 与 EtherType 之间插入 4 字节：

| 字段 | 长度 | 说明 |
|------|------|------|
| TPID | 2 字节 | 固定为 `0x8100`，标识这是一个 VLAN 标签 |
| PCP | 3 bit | 802.1p 优先级，0~7 |
| DEI | 1 bit | 丢弃合格指示（旧标准称 CFI），标记能否被丢弃 |
| VID | 12 bit | VLAN ID，0~4095，其中 0 和 4095 保留 |

打上 VLAN 标签后帧长增加到最大 **1522 字节**，因此带 Tag 的接口 MTU 常配置为 1504（对 IP 载荷而言仍是 1500）。VLAN 的核心价值是**在同一物理链路上划分多个逻辑广播域**，隔离二层广播，同时让帧能够跨交换机透传。

### 5. ARP 与链路层的关系

ARP（Address Resolution Protocol）解决的是**三层地址到二层地址的映射**问题：已知对端的 IP 地址，如何获得它的 MAC 地址以便封装帧。

1. 主机 A 要发送 IP 包给同链路的 B，先查本地 **ARP 缓存**（Linux 下用 `ip neigh` 查看）。
2. 缓存未命中时，A 发送 **ARP 请求**：目的 MAC 为广播地址 `FF-FF-FF-FF-FF-FF`，询问"谁的 IP 是 B，请回复 MAC"。
3. 链路上所有节点都会收到请求，但只有 B 响应。B 返回 **ARP 应答**（单播），同时把 A 的 IP/MAC 映射记录进自己的缓存。
4. A 收到应答后更新缓存，封装以太网帧发送。

| 对比项 | ARP 请求 | ARP 应答 |
|--------|----------|----------|
| 目的 MAC | 广播 `FF-FF-FF-FF-FF-FF` | 请求方单播 MAC |
| 方向 | 请求方 → 链路上所有节点 | 目标主机 → 请求方 |
| EtherType | `0x0806` | `0x0806` |

ARP 报文直接封装在以太网帧中，**不经过 IP 层**，这也是把 ARP 归为链路层相关协议的原因。两个值得注意的点：

- **免费 ARP（Gratuitous ARP）**：主机主动广播自己的 IP/MAC 映射，用于检测 IP 冲突、设备切换时通知邻居更新缓存。
- **ARP 欺骗**：由于 ARP 协议不做真实性校验，攻击者可以伪造应答，把网关 IP 映射到自己的 MAC，实现中间人攻击。常见防护手段是静态 ARP 表或 DHCP Snooping。

### 6. 链路层设备：网桥与交换机

#### 6.1 设备对比

| 设备 | 工作层次 | 转发依据 | 隔离冲突域 | 隔离广播域 |
|------|----------|----------|------------|------------|
| 集线器（Hub） | 物理层 | 无，广播所有端口 | 否 | 否 |
| 网桥（Bridge） | 数据链路层 | MAC 地址 | 是 | 否 |
| 二层交换机（Switch） | 数据链路层 | MAC 地址（多端口网桥） | 是 | 否 |
| 路由器（Router） | 网络层 | IP 地址 | 是 | 是 |

#### 6.2 交换机工作原理：MAC 地址表学习

交换机是**多端口的透明网桥**，核心机制是 MAC 地址表的自学习（Self-learning）：

1. **学习（Learn）**：收到帧时，记录 `源 MAC → 入端口` 的映射到 MAC 地址表。
2. **查找（Lookup）**：根据帧的目的 MAC 查表。
3. **转发/过滤（Forward/Filter）**：命中则只从对应端口转发（单播）；目的 MAC 是广播/组播或查表未命中，则从除入端口外**泛洪（Flood）**到所有端口。
4. **老化（Aging）**：表项有生存时间（默认约 300 秒），期间无流量则删除，避免因终端迁移产生错误转发。

| MAC 表项组成 | 示例 |
|--------------|------|
| MAC 地址 | `00:1A:2B:3C:4D:5E` |
| 关联端口 | `Port 3` |
| 老化时间 | 300 秒（可配置） |

> 交换机**不修改帧内容**（不做源 MAC 替换，也不重写 CRC），因此对终端透明，这就是"透明网桥"的由来。VLAN 划分后，MAC 地址表还需绑定 VLAN，同一 MAC 在不同 VLAN 中独立学习。

### 7. MTU 与路径 MTU 发现

#### 7.1 MTU 概念

**MTU（Maximum Transmission Unit）**指链路层**载荷（Payload）**能承载的最大字节数，即一个帧中 IP 数据报的上限。不同链路类型的 MTU 不同：

| 链路类型 | MTU |
|----------|-----|
| 以太网 | 1500 |
| 802.11（Wi-Fi） | 1500（常见） |
| PPPoE | 1492（扣除 8 字节 PPPoE 头） |
| 环回接口 | 65536 |
| Jumbo Frame（巨型帧） | 9000 |

#### 7.2 MTU 与 IP 分片

当 IP 数据报大于出接口 MTU 时，发送方会把数据报**分片（Fragmentation）**后再封装成多个帧：

- **IPv4**：支持分片，分片/重组由首部的 Identification、Flags、Fragment Offset 字段完成。
- **IPv6**：中间路由器**不分片**，只允许源主机通过分片扩展头分片，超出 MTU 的包直接丢弃并回 ICMPv6 报文。

#### 7.3 路径 MTU 发现（PMTUD）

**路径 MTU**是源到目的整条路径上所有链路 MTU 的最小值。PMTUD 的思路是让源主机主动探测这个最小值，避免中间节点分片：

1. 源主机发送一个较大的数据报，并置 **DF（Don't Fragment）位**。
2. 若某个中间链路的 MTU 较小，路由器丢弃该包并回送 ICMP 错误报文 `Fragmentation needed but DF set`（IPv4 类型 3 代码 4），其中携带该链路的 MTU 值。
3. 源主机按反馈值调小报文大小，重新发送，直到包能顺利到达，从而收敛到路径 MTU。

常见问题与对策：

- **PMTUD 黑洞**：某些防火墙/路由器静默丢弃需分片的 ICMP 报文，导致源主机永远收不到反馈、连接挂起。常见对策是在 TCP 侧做 **MSS Clamping**（把 SYN 中的 MSS 值钳制到较小值，如 1452/1400），从源头避免大包。
- 隧道场景（GRE、VXLAN、PPPoE）都会增加头部开销，使实际可用 MTU 变小，这也是宽带拨号 MTU 常配 1492 的原因。

| 主题 | 一句话结论 |
|------|------------|
| 帧结构 | 目的 MAC（6B）+ 源 MAC（6B）+ Type（2B）+ 载荷（46~1500B）+ FCS（4B） |
