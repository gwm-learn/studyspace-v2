# TR-069 / CWMP

> 解决什么问题：运营商 ACS 如何远程管理 CPE：会话、RPC、数据模型、固件升级、诊断。
> 不解决：具体 ACS 平台实现；USP 见 [TR-369](02-TR-369.md)。

## 1. 角色与协议栈

```text
ACS（运营商）  ←── HTTP/HTTPS ──→  CPE（设备）
   管理服务器                         CWMP 客户端
```

| 角色 | 职责 |
|---|---|
| ACS | 下发配置、升级固件、采集状态、诊断 |
| CPE | 主动发起会话、执行 RPC、上报事件 |

- 传输：HTTP/HTTPS（常用 7547/443）。
- 会话由 **CPE 主动发起**，因此 CPE 在 NAT 后也能被管理。
- 编码：SOAP/XML。

## 2. 会话流程

```text
CPE ── Inform ─────────────► ACS
CPE ◄─ InformResponse ────── ACS
CPE ── Empty HTTP Response ► ACS
CPE ◄─ GetParameterValues ── ACS
CPE ── Response ────────────► ACS
CPE ◄─ SetParameterValues ── ACS
...
CPE ── Empty HTTP Response ► ACS   （会话结束）
```

关键点：

- 一次 HTTP 事务一个 RPC；会话由 CPE 的"空响应"结束。
- `Inform` 携带 Event Codes（0 BOOTSTRAP、1 BOOT、2 PERIODIC、6 CONNECTION REQUEST、4 VALUE CHANGE 等）。
- 会话中 ACS 可以连续下发多个 RPC。

## 3. 核心 RPC

| RPC | 方向 | 作用 |
|---|---|---|
| Inform | CPE→ACS | 会话开始、上报事件/参数 |
| GetParameterValues | ACS→CPE | 读参数 |
| SetParameterValues | ACS→CPE | 写参数 |
| GetParameterNames | ACS→CPE | 枚举参数树 |
| AddObject / DeleteObject | ACS→CPE | 增删实例 |
| Download | ACS→CPE | 下载固件/配置 |
| Upload | ACS→CPE | 上传日志/诊断 |
| Reboot / FactoryReset | ACS→CPE | 重启/恢复出厂 |
| ScheduleInform | ACS→CPE | 预约上报 |
| ConnectionRequest | ACS→CPE | 触发 CPE 主动建会话 |

## 4. Connection Request（NAT 穿透）

CPE 在 `Inform` 中上报 `ConnectionRequestURL` 与认证信息；ACS 向该 URL 发 HTTP 请求，CPE 收到后主动发起新会话。

| 方式 | 说明 |
|---|---|
| Connection Request | 最常用；需要 CPE 的 WAN 可达或端口映射 |
| STUN | CPE 获取 NAT 映射，ACS 用 UDP 触发；适合受限网络 |
| 长连接 | 部分实现用 WebSocket；TR-369 更常见 |

常见失败：URL 不可达、认证失败、ACS 源 IP 被防火墙拦截、CPE 未监听。

## 5. 数据模型

| 模型 | 说明 |
|---|---|
| TR-098 | InternetGatewayDevice（IGD）数据模型，老设备 |
| TR-181 | Device:2 数据模型，新设备/多业务 |
| TR-104 | VoIP |
| TR-140 | 存储 |
| TR-157 | 组件对象（BulkData、FaultMgmt 等） |

常见参数树（TR-181 风格）：

```text
Device.
├── DeviceInfo.               # 厂商/型号/序列号/固件版本
├── ManagementServer.         # ACS URL、认证、周期上报
├── IP.Interface.{i}.         # WAN/LAN 接口、地址、DHCP
├── Ethernet.Interface.{i}.
├── WiFi.Radio.{i}. / SSID.{i}. / AccessPoint.{i}.
├── Hosts.Host.{i}.           # 终端列表
├── Firewall.
├── NAT.PortMapping.{i}.
├── PPP.Interface.{i}.
├── Services.
└── FaultMgmt. / BulkData.
```

实现要点：
- 参数路径必须与模型一致；厂商扩展放在 `X_VENDOR_` 命名空间。
- 读写要校验类型/范围/权限；只读参数写入应返回 fault。
- 参数变化要触发 VALUE CHANGE 事件（按需）。

## 6. 固件下载

```text
ACS ── Download(URL, FileType, FileSize, Checksum) ──► CPE
CPE ── 下载 ── 校验 ── 写分区 ── 重启 ──► Inform(1 BOOT)
```

要点：

| 项 | 说明 |
|---|---|
| FileType | `1 Firmware Upgrade Image` 等 |
| 校验 | 大小、哈希、签名 |
| 断点/重试 | 网络差时必须有 |
| 回滚 | A/B 或失败回退 |
| 升级窗口 | 避免业务高峰 |
| 状态上报 | Download 响应 + 后续 Inform |

## 7. 安全

- ACS 认证：Basic/Digest；生产必须 HTTPS + 证书校验。
- CPE 认证：Connection Request 的用户名/口令。
- 不要关闭证书校验；不要在日志中打印口令。
- 限制 ACS 源 IP；防火墙只放行必要端口。

## 8. 联调与排障

```bash
# CPE 侧抓包
tcpdump -ni any -s0 -w tr069.pcap 'tcp port 7547 or tcp port 443'

# 检查管理服务器配置
uci show tr069
ps | grep -i cwmp
```

| 现象 | 首查 |
|---|---|
| 不上报 | ACS URL/DNS/路由/防火墙、时间是否正确 |
| 401/403 | 认证配置、证书 |
| Connection Request 失败 | URL 可达性、端口映射、CPE 监听 |
| SetParameterValues 失败 | 参数路径/类型/权限 |
| 升级失败 | URL、校验、空间、分区、回滚 |
| 周期性断 | 会话超时、NAT 老化、ACS 限流 |
