# OpenWrt 隧道接入范式（UCI + 防火墙）

> 解决什么问题：WireGuard/ZeroTier/L2TP 等隧道接入 OpenWrt 时，UCI 与防火墙的共性步骤。
> 不解决：各协议自身的报文与密钥协商（见各自协议卡）。

## 1. 共性模型

```text
隧道接口（tun/wg/zt）
   │  分配地址/路由
   ▼
防火墙区域（zone）
   │  forward / input / masq / mtu_fix
   ▼
转发规则（可选）
   │  允许 LAN → VPN、VPN → LAN
   ▼
DNS/策略路由（可选）
```

## 2. 五步接入法

### 2.1 建接口

```uci
config interface 'vpn0'
    option proto 'none'
    option device 'wg0'      # 或 tun0 / ztxxxx
```

### 2.2 配地址与路由

- 点对点：给隧道接口一个 /32 或 /24。
- 站点到站点：加静态路由指向对端网段。
- 默认路由走隧道：谨慎，容易断管理。

```uci
config route
    option interface 'vpn0'
    option target '10.2.0.0/24'
    option gateway '10.0.0.2'
```

### 2.3 划防火墙区域

```uci
config zone
    option name 'vpn'
    option input 'REJECT'
    option output 'ACCEPT'
    option forward 'REJECT'
    list network 'vpn0'

config forwarding
    option src 'lan'
    option dest 'vpn'

config forwarding
    option src 'vpn'
    option dest 'lan'
```

### 2.4 放行必要端口

| 协议 | 端口 | 说明 |
|---|---|---|
| WireGuard | UDP 51820 | 入站 |
| L2TP | UDP 1701 + ESP | 需 proto 47 |
| IPsec | UDP 500/4500 + ESP | NAT-T |
| ZeroTier | UDP 9993 | 出站为主 |

### 2.5 验证

```bash
ip addr show vpn0
ip route
nft list ruleset | grep -A5 vpn
ping -I vpn0 10.0.0.1
tcpdump -ni vpn0
```

## 3. 常见坑

| 现象 | 原因 |
|---|---|
| 隧道 up 但不通 | 没有 forwarding、路由缺失 |
| 能 ping 隧道对端，不能访问对端 LAN | 对端未回程路由/未放行 |
| NAT 后只有单向 | 缺少 masq 或端口映射 |
| 管理面失联 | 默认路由被隧道抢走 |
| MTU 黑洞 | 隧道 overhead，需 `mtu_fix`/调 MTU |
| DNS 不解析 | DNS 未指向隧道侧 |

## 4. 最小检查表

- [ ] 接口存在且 up。
- [ ] 地址/路由正确。
- [ ] 防火墙 zone 与 forwarding 正确。
- [ ] 入站端口/协议放行。
- [ ] MTU 与 MSS 正确。
- [ ] DNS/策略路由符合预期。
- [ ] 断线重连/开机自启。
