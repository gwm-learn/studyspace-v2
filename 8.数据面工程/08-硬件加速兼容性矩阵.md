# 硬件加速兼容性矩阵

> 解决什么问题：开了 flow offload/HNAT/PPE 后，QoS/抓包/端口映射/VLAN 失效；如何回归。
> 不解决：具体 SoC 加速驱动实现（按厂商）。

## 1. 加速层次

| 层次 | 机制 | 谁做 |
|---|---|---|
| 软件快路径 | flow offload（nf_flow_table） | 内核 |
| 硬件 NAT | HNAT | SoC |
| 包处理引擎 | PPE | SoC |
| 交换机 | DSA 硬件转发 | 交换机 |
| 驱动层 | XDP/eBPF | 网卡/驱动 |

## 2. 兼容性矩阵（按平台填）

| 功能 | 软件转发 | flow offload | HNAT/PPE |
|---|---|---|---|
| NAT | ✅ | ✅ | ✅/需驱动 |
| 端口映射 | ✅ | ✅ | ⚠️ |
| QoS/TC | ✅ | ❌ | ❌ |
| VLAN | ✅ | ⚠️ | ⚠️ |
| PPPoE | ✅ | ⚠️ | ⚠️ |
| IPv6 | ✅ | ✅ | ⚠️ |
| 抓包 | ✅ | ⚠️ | ❌ |
| ALG | ✅ | ⚠️ | ❌ |
| 连接数 | 中 | 高 | 高 |
| CPU 占用 | 高 | 低 | 最低 |

> ⚠️ 表示“取决于芯片/驱动/配置”，必须实测。

## 3. 为什么冲突

- 加速后后续包绕过协议栈 → `tcpdump` 看不到。
- QoS 依赖 `tc` 排队 → 包被短路，队列不生效。
- 硬件 NAT 可能只处理简单五元组 → 端口映射/ALG 失效。
- VLAN/PPPoE 封装变化 → 流表匹配不到。
- 连接跟踪/防火墙规则可能被绕过。

## 4. 回归测试

```text
开/关加速各跑一遍：
NAT、端口映射、ALG、QoS、VLAN、PPPoE、IPv6、抓包、并发
```

| 项 | 判据 |
|---|---|
| 吞吐 | 提升 |
| CPU | 下降 |
| 时延 | 不恶化 |
| 功能 | 不回归 |
| 温度 | 不超阈值 |
| 抓包 | 知道能否看到 |

## 5. 验证命令

```bash
# 流表/加速状态
nft list ruleset | grep -i flow
cat /proc/net/nf_conntrack | wc -l
dmesg | grep -i -E 'hnat|ppe|offload'

# 吞吐/CPU
iperf3 -c server -t 30 -P 4
mpstat -P ALL 1
top -H
```

## 6. 选型建议

- 可观测性优先：软件够用就不开硬件加速。
- 需要 QoS/抓包/复杂 NAT：慎用硬件加速。
- 开加速必须回归，不接受“只测吞吐”。
- 记录平台/驱动/固件版本。

## 7. 常见坑

| 现象 | 原因 |
|---|---|
| 开了加速抓不到包 | 后续包不走协议栈 |
| QoS 失效 | 绕过 tc |
| 端口映射异常 | 硬件流表未处理 |
| PPPoE 无效 | 驱动不支持 |
| 小包性能差 | 加速对小包收益有限 |
| 温度升高 | 加速单元功耗 |
