# 构建系统选型

> 解决什么问题：项目该用 OpenWrt、Buildroot、Yocto 还是厂商 SDK；迁移成本多大。
> 不解决：具体构建命令（见各自笔记）。

## 1. 决策维度

| 维度 | 问题 |
|---|---|
| 产品形态 | 路由器/网关/ODU/固定功能？ |
| 功能 | 需要 opkg/LuCI/防火墙/协议栈？ |
| 体积/启动 | 镜像多大、启动多快？ |
| 升级 | 需要 A/B/回滚/差分？ |
| 维护周期 | 1 年还是 5 年？ |
| 团队 | 熟悉哪个？ |
| 芯片支持 | 厂商 BSP 基于哪个？ |
| 合规 | license/SBOM/认证？ |

## 2. 对比

| 项 | OpenWrt | Buildroot | Yocto |
|---|---|---|---|
| 定位 | 路由器发行版 | 小型根文件系统 | 通用发行版 |
| 包管理 | opkg/apk | 无/可加 | rpm/deb/ipk |
| 配置 | menuconfig+feeds | menuconfig | layer/recipe |
| 升级 | sysupgrade | 自建 | 自建/RAUC |
| 学习曲线 | 中 | 低 | 高 |
| 生态 | 网络强 | 小而全 | 工业强 |
| 多产品 | 中 | 弱 | 强 |
| 启动/体积 | 中 | 小 | 大 |

## 3. 典型选择

```text
路由器/CPE/网关，需要 LuCI/opkg/防火墙 → OpenWrt
固定功能、小体积、快速启动 → Buildroot
多产品/长维护/强定制/工业 → Yocto
厂商已给 BSP → 先基于 BSP 打通，再评估迁移
```

## 4. 迁移成本

| 方向 | 主要工作 |
|---|---|
| OpenWrt → Yocto | 重写配方/配置/升级；驱动适配 |
| Buildroot → OpenWrt | 包管理/网络框架/LuCI |
| Yocto → OpenWrt | 层/配方拆解；包管理 |
| vendor → 主线 | 驱动/DTS/补丁上游化 |

不要低估：升级/认证/驱动/工具链都要重做。

## 5. 评估方法

1. 列需求（功能/体积/升级/维护）。
2. 做 2 周 PoC：启动+网络+升级。
3. 评估驱动支持/厂商配合。
4. 评估团队学习成本。
5. 记录 ADR（选项/代价/复审条件）。

## 6. 常见误区

| 误区 | 纠正 |
|---|---|
| 哪个火用哪个 | 按产品/维护选 |
| 先定制再补升级 | 升级要从第一天设计 |
| 直接改上游树 | 用 layer/patch/feed |
| 忽略许可 | SBOM/合规 |
| 忽略工具链 | 固定版本/容器 |

## 7. 检查表

- [ ] 需求/约束清单。
- [ ] PoC 验证启动/网络/升级。
- [ ] 驱动/BSP 支持。
- [ ] 维护/升级/回滚。
- [ ] 许可/SBOM。
- [ ] ADR 记录。
