# 厂商 SDK 与 BSP

> 解决什么问题：拿到 vendor SDK 后如何快速 bring-up、如何不被厂商树绑死、如何管理补丁。
> 不解决：具体芯片寄存器/驱动（按厂商文档）。

## 1. SDK/BSP 组成

| 部分 | 内容 |
|---|---|
| Bootloader | U-Boot/ATF/预编译 BL2 |
| 内核 | vendor 分支 + 补丁 |
| 驱动 | Wi-Fi/交换/PHY/加速 |
| 根文件系统 | 预编译 rootfs/SDK |
| 工具 | 烧录、校准、产测 |
| 文档 | datasheet/硬件设计指南 |

## 2. 接手顺序

```text
版本/芯片 → 编译官方镜像 → 串口启动 → 网络/存储 → 外设 → 定制
```

1. 记录 SDK 版本、内核版本、工具链、commit。
2. 用官方配置编译一次，确认环境。
3. 串口抓启动，确认 bootargs/分区/DTS。
4. 验证网口/Wi-Fi/USB/存储。
5. 再开始改。

## 3. 代码管理

| 策略 | 说明 |
|---|---|
| vendor 树只读 | 不改，作为基线 |
| 项目补丁集 | `git format-patch`/quilt |
| 分层 | 自己的 board/package 放外部 |
| 升级 | 定期 rebase/评估 |

- 每个补丁有原因/作者/日期。
- 不直接改 vendor 驱动；用 patch 覆盖。
- 记录“哪些补丁是必须的”。

## 4. 常见风险

| 风险 | 对策 |
|---|---|
| 内核太旧/CVE | 评估升级/缓解 |
| 私有补丁不可维护 | 补丁清单/上游化 |
| 绑定工具链 | 容器化/固定版本 |
| 闭源驱动 | 许可/长期支持 |
| 文档缺失 | 实测/记录 |
| 校准/产测工具缺失 | 提前索取 |

## 5. Bring-up 检查表

- [ ] 供电/时钟/复位。
- [ ] 串口启动日志。
- [ ] DDR/存储识别。
- [ ] 网口/Wi-Fi/USB。
- [ ] 分区/factory 数据。
- [ ] 升级/恢复。
- [ ] 校准/产测。

## 6. 与主线合并

- 先对比 DTS/驱动差异。
- 能上游的补丁上游；不能的保留。
- 不追求“完全主线”，追求“可维护”。
- 记录差异与原因。

## 7. 常见坑

| 现象 | 原因 |
|---|---|
| 编译失败 | 工具链/依赖/路径 |
| 启动卡住 | DDR/电源/DTS |
| 网口不通 | PHY/交换机配置 |
| Wi-Fi 无校准 | factory/校准数据 |
| 升级变砖 | 分区/镜像不匹配 |
