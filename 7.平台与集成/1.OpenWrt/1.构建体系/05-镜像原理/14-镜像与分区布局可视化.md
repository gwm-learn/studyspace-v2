# 镜像与分区布局可视化


### 13.1 理解两类镜像的本质区别

MT7981 的镜像分为两大类，理解它们的设计意图是看懂布局的前提：

| 类型 | 用途 | 包含内容 | 烧录方式 |
|------|------|---------|---------|
| **sysupgrade 镜像** | 在线升级 | 仅有 kernel + rootfs（无 BL2/FIP） | `fit_do_upgrade` / `nand_do_upgrade` 写入 UBI 卷 |
| **factory 镜像** | 工厂量产 / 全量烧录 | BL2 + FIP + kernel + rootfs（全套） | 全区或分区裸写（用编程器或 BootROM 下载模式） |

**sysupgrade 镜像不包含 bootloader**，因为 BootROM 和 BL2 / FIP 出厂就烧好了，升级固件不需要重刷它们。这样做的好处是：
- 升级包体积小（不含 ~8MB 的 BL2+FIP）
- 升级时不会意外刷坏 bootloader 导致变砖

**factory 镜像包含全套组件**，因为工厂量产时需要一次性把完整系统写入空白 Flash。

### 13.2 Flash 物理布局（MT7981 各启动介质）

以下布局数据来自 `mt7981b-openwrt-one.dts`（SPI-NAND / SPI-NOR / eMMC）及 `filogic.mk` 的 `Build/mt798x-gpt` 分区表定义。

#### SPI-NAND Flash（最常见，大多数商业路由器使用，以 openwrt_one 为例）

布局数据来自 `target/linux/mediatek/dts/mt7981b-openwrt-one.dts`（第 322-345 行）：

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│  MT7981 SPI-NAND Flash (openwrt_one, 总容量 256MB)                          │
│                                                                                          │
│  ┌──────────────┬─────────────────────────────────────────────────────────────┐  │
│  │ 0x000000     │ partition@0 "bl2" (1MB, 只读)                          │  │
│  │  0 ~ 1MB     │ BootROM 从本分区起始地址加载 BL2 到 SRAM              │  │
│  │              │ ┌──────────────────────────────────────────────┐     │  │
│  │              │ │ mt7981-spim-nand-ubi-ddr4-bl2.img          │     │  │
│  │              │ │ (ATF 构建, mkimage 包装头, 含 BL2 入口)     │     │  │
│  │              │ └──────────────────────────────────────────────┘     │  │
│  │              └─────────────────────────────────────────────────────┘  │
│  ├──────────────┼─────────────────────────────────────────────────────────────┤  │

│  │  1 ~ 256MB   │ ┌──────────────────────────────────────────────────┐    │  │
│  │              │ │ UBI Volume: fit (volname="fit")             │    │  │
│  │              │ │ ┌──────────────────────────────────────────┐ │    │  │
│  │              │ │ │ kernel FIT (Image.lzma + DTB)        │ │    │  │
│  │              │ │ ├──────────────────────────────────────────┤ │    │  │
│  │              │ │ │ U-Boot proper (nt-fw, 嵌入 firmware    │ │    │  │
│  │              │ │ │         子镜像, 替代独立 FIP 分区)       │ │    │  │
│  │              │ │ │ BL31 / soc-fw (EL3 Runtime)            │ │    │  │
│  │              │ │ └──────────────────────────────────────────┘ │    │  │
│  │              │ └──────────────────────────────────────────────────┘    │  │

│  │              │ │ UBI Volume: rootfs (squashfs, autoresize)     │    │  │
│  │              │ └──────────────────────────────────────────────────┘    │  │
│  │              │ ┌──────────────────────────────────────────────────┐    │  │
│  │              │ │ UBI Volume: rootfs_data (JFFS2 overlay)       │    │  │
│  │              │ └──────────────────────────────────────────────────┘    │  │
│  │              │ ┌──────────────────────────────────────────────────┐    │  │
│  │              │ │ UBI Volume: ubootenv × 2 (各 1MiB)              │    │  │
│  │              │ └──────────────────────────────────────────────────┘    │  │
│  └──────────────┴─────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**关键理解**：openwrt_one 的 SPI-NAND 布局非常精简——仅 `partition@0 "bl2"` + `partition@580000 "ubi"` 两个分区。**没有独立的 FIP 分区**；U-Boot 可能嵌入 UBI:fit volume 中的 firmware 子镜像（通过 mkimage 打包），或由 BootROM 特殊加载路径处理。BootROM 按顺序从 BL2 → UBI → fitblk 依次加载：
1. BootROM 从 `partition@0 (bl2)` 加载 BL2 到 SRAM
2. BL2 从 UBI:fit 加载 kernel FIT（含 U-Boot）
3. U-Boot 挂载 UBI，从 `UBI:fit` 读取 kernel FIT
4. fitblk 将 rootfs 子镜像暴露为块设备

> **变体差异**：`openwrt_one` 的 SPI-NAND DTS 布局更简化（`mt7981b-openwrt-one.dts`），只有 `partition@0 "bl2"` + `partition@580000 "ubi"` 两个分区，无独立的 u-boot-env / factory / fip 分区——U-Boot 环境变量与 rootfs 一起打包进 UBI，U-Boot 可能嵌入 UBI:fit 或通过其他机制加载。

**SPI-NAND 启动时序**（openwrt_one）：
```
BootROM → BL2 (bl2 分区) → UBI:fit (kernel FIT, 含 U-Boot) → fitblk → rootfs
```

#### SPI-NOR Flash（通常用于支持 Dual Flash 的设备）

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│  MT7981 SPI-NOR Flash (以 openwrt_one NOR 分区为例)                              │
│                                                                                  │
│  ┌─────────────────────┬─────────────────────────────────────────────────────┐  │
│  │ 0x00000 (0KB)       │ BL2_NOR 分区 (256KB)                                 │  │
│  │                     │ mt7981-nor-ddr4-bl2.img                              │  │
│  │                     │ BootROM 从 SPI-NOR 加载 BL2                           │  │
│  ├─────────────────────┼─────────────────────────────────────────────────────┤  │
│  │ 0x40000 (256KB)     │ FACTORY 分区 (512KB)                                  │  │
│  │                     │ 校准数据: MAC 地址、Board ID、Wi-Fi 校准参数           │  │
│  │                     │ (nvmem layout, /dev/mtd* 设备节点)                    │  │
│  ├─────────────────────┼─────────────────────────────────────────────────────┤  │
│  │ 0x100000 (1MB)      │ FIP_NOR 分区 (512KB)                                  │  │
│  │                     │ mt7981_openwrt_one-nor-u-boot.fip                     │  │
│  │                     │ (BL31 + U-Boot proper，打包在 FIP 中)                 │  │
│  ├─────────────────────┼─────────────────────────────────────────────────────┤  │
│  │ 0x180000 (1.5MB)    │ RECOVERY 分区 (~12.5MB)                               │  │
│  │                     │ 恢复用 kernel FIT (可独立启动)                        │  │
│  └─────────────────────┴─────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**注意**：NOR Flash 的 BootROM 加载 BL2_NOR 分区后，BL2 不会去 NOR 找 FIP（因为 FIP_NOR 分区不在 BL2 的直接加载路径上）。实际启动时，BL2 仍然从 SPI-NAND 的 BL2 分区加载，FIP 从 SPI-NAND 的 UBI:fit 卷加载。NOR 分区主要用于：出厂校准数据存储、Recovery 镜像、FIP 备份。

**eMMC 启动流程**：BootROM 支持 eMMC 启动，从 Boot Partition 1 加载 BL2 → BL2 加载 Boot Partition 2 中的 FIP → BL31 → U-Boot → 读取 FAT32 分区中的 kernel FIT → bootm。

### 13.3 镜像文件内部结构（sysupgrade.itb vs factory.ubi vs factory.bin）


**sysupgrade.itb 中 rootfs 的位置取决于 `external-with-rootfs` vs `external-static-with-rootfs`**：
- `external-with-rootfs`：**rootfs 不在本镜像中**，从 UBI:rootfs 卷读取（需要 fitblk）。sysupgrade 只更新 kernel。
- `external-static-with-rootfs`：rootfs 在本镜像中，作为 static 卷打包进 UBI（少见，abt_asr3000 使用）。

**factory.ubi 与 sysupgrade.itb 的关键区别**：
- factory.ubi 包含 **完整可启动系统**（kernel + rootfs 在同一个 UBI 容器内）
- sysupgrade.itb 只包含 kernel + DTB，rootfs 独立存在于 UBI:rootfs 卷
- factory.ubi 的 kernel 卷是 **STATIC 卷**（固定大小，不自动调整）
- factory.ubi 的 rootfs 卷是 **autoresize 卷**（自动扩展占满剩余空间）

### 13.4 启动流程中的组件定位图

以下展示三种典型启动路径中，每个阶段读取哪个 Flash 区域：

```
路径 A: SPI-NAND 启动（abt_asr3000 / 多数商业 NAND 设备）
══════════════════════════════════════════════════════════════

  Flash MTD 分区                组件                           加载到
  ──── ────────────                           ────                           ──────
  partition@0 (bl2)    →    BL2 (mt7981-spim-nand-*-bl2.img)    SRAM
       ↓
  partition@380000 (fip) →    FIP (mt7981-*-u-boot.fip)           DRAM
  (raw MTD, 不是 UBI)         ├─ BL31 (soc-fw, EL3 Runtime)           │
                              └─ U-Boot proper (nt-fw)                  │
       ↓                                                                 │
  BL31 (在 FIP 内部)   →    EL3 Runtime                                  DRAM
       ↓                                                                 │
  U-Boot proper          →    Bootloader                                   DRAM
  (FIP 中的 nt-fw)            │                                             │
       ↓                                                                 │
  partition@580000 (ubi) →    UBI:fit (kernel FIT)                    DRAM
  (raw MTD, UBI 层)          ├─ kernel (Image.lzma)                       │
  │                           ├─ DTB (mt7981b-xxx.dtb)                       │
  │                           └─ (可选) rootfs@1 (external-with-rootfs)     │
       ↓                                                                 │
  UBI:rootfs 卷           →    squashfs → fitblk → /dev/fit0     / (rootfs)
       ↓                                                                 │
  /dev/ubi0_0             →    rootfs_data (JFFS2 overlay)         /overlay
```

**路径 A 启动时序**：
1. **BootROM** 从 `partition@0 (bl2)` 读取 BL2 到 SRAM（BootROM 硬编码偏移）
2. **BL2** 从 `partition@380000 (fip)` 读取 FIP（BL2 知道 fip 分区的固定偏移）
3. **FIP** 中 BL31 初始化 EL3 环境，**U-Boot proper** 接管
4. **U-Boot** 使用 `ubi part ubi` 挂载 UBI，从 `UBI:fit` 读取 kernel FIT
5. **fitblk** 驱动读取 `/chosen/rootdisk` phandle，将 FIT 中的 rootfs 子镜像暴露为 `/dev/fit0` 块设备
6. **Linux** 从 `/dev/fit0` (squashfs) 挂载根文件系统

**关键区别**：FIP 是 raw MTD 分区（`partition@380000 "fip"`），**不在 UBI 内**。BL2 通过 NAND Romcode 直接访问 raw 分区；UBI 是 Linux 内核的 FTL 层，需等 Linux 启动后才能使用。

**镜像类型组成对照表**（FIP 位置因设备而异）：

| 镜像文件 | BL2 | FIP | kernel FIT | rootfs | 元数据 | 典型用途 | FIP 位置 |
|---------|-----|-----|-----------|--------|--------|---------|---------|
| `sysupgrade.itb` | ❌ | ❌ | ✅ 含 kernel+DTB | ❌ (在 UBI 中) | ✅ JSON+sha256 | 在线升级 | N/A |
| `sysupgrade.bin` (非 FIT) | ❌ | ❌ | ✅ kernel | ✅ squashfs | ✅ | 传统 NAND 升级 | N/A |
| `factory.ubi` | ❌ | ❌ | ✅ kernel (UBI static 卷) | ✅ UBI dynamic 卷 | ❌ | 工厂量产 (UBI) | N/A |
| `snand-factory.bin` | ✅×4 (NAND) | ❌ (U-Boot 可能嵌在 UBI:fit 中) | ✅ kernel (UBI 内) | ✅ UBI 内 | ❌ | NAND 全量烧录 | 无独立 fip 分区 |
| `nor-factory.bin` | ✅ (NOR) | ✅ (NOR) | Recovery 在 NOR | ❌ | ❌ | NOR Flash 烧录 | NOR FIP_NOR 分区 |
| `emmc-preloader.bin` | ✅ (eMMC) | ❌ | ❌ | ❌ | ❌ | eMMC BL2 单独烧录 | N/A |
| `emmc-bl31-uboot.fip` | ❌ | ✅ (eMMC) | ❌ | ❌ | ❌ | eMMC FIP 单独烧录 | eMMC Boot Part 2 |
| `sdcard.img.gz` | ✅ (SD GPT) | ✅ (SD GPT) | Recovery (SD GPT) | ✅ (SD GPT) | ❌ | SD 卡全量镜像 | SD GPT Partition 2 |

**FIP 位置因设备而异**：
- **SNAND 设备**（abt_asr3000 等）：FIP 是独立的 raw MTD 分区 `partition@380000 "fip"`（128KB）
- **openwrt_one snand**：无独立 FIP 分区，U-Boot 可能嵌入 UBI:fit volume 中的 firmware 子镜像
- **NOR 设备**（openwrt_one nor）：FIP 是独立的 `partition@100000 "fip-nor"`（512KB）
- **eMMC 设备**：FIP 存放在 eMMC Boot Partition 2

**为什么 sysupgrade 镜像不需要 BL2/FIP？** 因为：
1. 升级时 BootROM → BL2 → FIP → U-Boot 的路径已经固化
2. 升级只替换 kernel FIT（写入 UBI:fit 卷）和 rootfs（UBI:rootfs 卷）
3. 如果升级包含 BL2/FIP，一旦中途断电，设备将变砖（无 bootloader 恢复）

**为什么 snand-factory.bin 没有独立 FIP？** 因为 openwrt_one snand 变体的 DTS 没有定义独立 `fip` 分区，U-Boot 可能被嵌入 UBI:fit volume（通过 mkimage "firmware" 子镜像）。而 abt_asr3000 等设备的 DTS 定义了 `partition@380000 "fip"`，snan-factory.bin 若基于此类设备则会包含独立 FIP 分区。
