# Qt 核心机制

> 解决什么问题：界面卡死、槽不触发、跨线程崩溃、交叉编译失败。
> 不解决：具体控件样式/QML 动画。

## 1. 对象模型

- `QObject` 提供信号槽、事件、父子对象树。
- 父对象析构时自动删除子对象。
- `Q_OBJECT` 宏触发 MOC 生成元对象代码。
- 对象有线程亲和（thread affinity），默认属于创建它的线程。

## 2. 信号槽

```cpp
connect(sender, &Sender::valueChanged,
        receiver, &Receiver::onValueChanged,
        Qt::AutoConnection);
```

| 连接类型 | 行为 |
|---|---|
| Auto | 同线程直连，跨线程队列 |
| Direct | 立即调用（发送者线程） |
| Queued | 投递到接收者线程事件循环 |
| BlockingQueued | 队列 + 阻塞等待（慎用） |

规则：

- 跨线程默认用 Queued。
- 槽的参数要可拷贝/注册元类型。
- 连接失败要检查返回值/日志。
- 对象销毁后连接自动断开。

## 3. 事件循环

```cpp
int main(int argc, char** argv) {
  QApplication app(argc, argv);
  MainWindow w; w.show();
  return app.exec();
}
```

- `exec()` 循环分发事件（鼠标/键盘/定时器/网络/信号）。
- 主线程阻塞 = 界面无响应。
- 耗时操作放 `QThread`/线程池，结果用信号回主线程。
- `processEvents()` 谨慎使用，可能导致重入。

## 4. 线程

| 方式 | 说明 |
|---|---|
| `QThread` + `moveToThread` | 推荐： worker 对象移到线程 |
| 继承 `QThread::run` | 简单，但对象仍在旧线程 |
| `QtConcurrent` | 任务并行 |
| 线程池 | 大量短任务 |

规则：

- UI 只能在主线程更新。
- 不要跨线程直接调用 QObject 方法（除非线程安全）。
- 退出时 `quit()` + `wait()`。

## 5. Model/View

- `QAbstractItemModel` 提供数据，View 负责显示。
- `dataChanged`/`beginInsertRows` 等信号通知视图。
- 大列表用 model，不要逐个控件。

## 6. QML / Qt Quick

- QML 描述 UI，C++ 提供模型/逻辑。
- 适合触屏/嵌入式；注意 GPU/内存/启动时间。
- C++ 与 QML 交互：`Q_PROPERTY`、`Q_INVOKABLE`、信号。
- 交叉编译要带 Qt Quick 模块与平台插件。

## 7. 交叉编译

```bash
./configure -prefix /opt/qt -opensource -confirm-license \
  -xplatform linux-aarch64-gnu-g++ -no-opengl
make -j$(nproc)
make install
```

要点：

- sysroot/toolchain 与目标一致。
- 平台插件（eglfs/linuxfb/xcb）按设备选。
- 部署时带 Qt 库/插件/字体。

## 8. 调试

```bash
QT_DEBUG_PLUGINS=1 ./app
QT_LOGGING_RULES="qt.*=true" ./app
```

| 现象 | 首查 |
|---|---|
| 界面卡死 | 主线程阻塞/死循环 |
| 槽不触发 | 连接失败/对象销毁/线程 |
| 启动失败 | 平台插件/库路径 |
| 花屏 | GPU/驱动/eglfs |
| 内存涨 | 对象未释放/信号未断 |

## 9. 常见坑

| 坑 | 说明 |
|---|---|
| 跨线程直接调 UI | 崩溃/未定义 |
| 在 worker 里 new QWidget | 不允许 |
| 信号参数用引用 | 队列连接需可拷贝 |
| 忘记 `Q_OBJECT` | 信号槽失效 |
| 阻塞 `exec()` | 无响应 |
