# C 项目实践

> 解决什么问题：把 C 语言知识落到可编译、可调试的小项目上；这些项目也是读源码的练习场。
> 说明：`项目实践/` 下的代码为练习项目，默认只读；做实验时复制到临时目录。

## 1. 项目清单

| 项目 | 类型 | 构建 | 能练什么 |
|---|---|---|---|
| [fw_params](%E9%A1%B9%E7%9B%AE%E5%AE%9E%E8%B7%B5/fw_params) | 配置/参数 | `make`（`src/Makefile`） | 配置解析、字符串、文件 IO |
| [produce](%E9%A1%B9%E7%9B%AE%E5%AE%9E%E8%B7%B5/produce) | 生产/工具 | `make`（`src/Makefile`） | 流程控制、日志、错误处理 |
| [mobile-mngr](%E9%A1%B9%E7%9B%AE%E5%AE%9E%E8%B7%B5/mobile-mngr) | 蜂窝管理 | `make` | 进程/线程、socket、状态机 |
| [ipc](%E9%A1%B9%E7%9B%AE%E5%AE%9E%E8%B7%B5/ipc) | 进程间通信 | `ipc/TEST` 用 CMake；`ipc/Template/7-socket` 用 make | 管道/消息队列/共享内存/socket |
| [net](%E9%A1%B9%E7%9B%AE%E5%AE%9E%E8%B7%B5/net) | 网络练习 | 无构建系统 | 独立 `.c` 的 socket/协议练习 |
| [schedule](%E9%A1%B9%E7%9B%AE%E5%AE%9E%E8%B7%B5/schedule) | 调度 | 无构建系统 | 定时/任务调度 |
| [gpio_customize](%E9%A1%B9%E7%9B%AE%E5%AE%9E%E8%B7%B5/gpio_customize) | 内核模块 | `make M=$PWD modules`（需内核源码） | 字符设备、GPIO、驱动模型 |

## 2. 建议练习顺序

```text
语言核心 → fw_params → net → ipc → produce → mobile-mngr → gpio_customize
```

| 阶段 | 目标 | 验证 |
|---|---|---|
| 1 | 能编译并跑通 | 每个项目 `make` 成功 |
| 2 | 能改一个功能 | 加参数/加日志/加错误处理 |
| 3 | 能定位一个 bug | gdb/strace/valgrind |
| 4 | 能写测试 | 至少 3 个边界用例 |
| 5 | 能讲清调用链 | 画一张流程图 |

## 3. 构建示例

```bash
# 普通 make 项目
cd 项目实践/fw_params && make

# CMake 项目
cd 项目实践/ipc/TEST && mkdir -p build && cd build && cmake .. && make

# 内核模块（需要内核源码树）
cd 项目实践/gpio_customize
make -C /path/to/linux M=$PWD modules
```

> 路径与内核版本按实际环境替换；不要在内核源码树里留下构建产物。

## 4. 每个项目要回答的问题

- 入口在哪？`main()` 之后第一件事是什么？
- 内存谁分配、谁释放？失败路径是否释放？
- 错误怎么传？返回值/errno/日志？
- 有没有并发？锁/信号/超时？
- 怎么验证？有没有可复现的输入？
