# 存储与分区

> 解决什么问题：固件、配置、factory 数据分别存在哪；升级/恢复为什么能保留配置。
> 不解决：文件系统实现细节（见 [进程与文件系统](../../6.%E7%B3%BB%E7%BB%9F%E8%BD%AF%E4%BB%B6/1.Linux%E5%86%85%E6%A0%B8%E4%B8%8E%E9%A9%B1%E5%8A%A8/02-%E8%BF%9B%E7%A8%8B%E7%AE%A1%E7%90%86%E4%B8%8E%E6%96%87%E4%BB%B6%E7%B3%BB%E7%BB%9F.md)）。

## 1. 三种常见介质

| 介质 | 典型容量 | 特点 | 常见布局 |
|---|---|---|---|
| SPI-NOR | 8–32 MB | 可靠、按扇区擦除、容量小 | U-Boot + env + kernel + rootfs + factory |
| SPI-NAND | 128–512 MB | 容量大、需坏块管理 | U-Boot + env + UBI(kernel/rootfs/rootfs_data) |
| eMMC | 4–64 GB | 容量大、有 FTL、分区灵活 | boot0/boot1 + GPT 分区 |

## 2. Linux 抽象层次

```text
Flash 驱动 → MTD 设备（/dev/mtdN, /dev/mtdblockN）
                 │
                 ├─ 直接文件系统（jffs2/ubifs）
                 └─ UBI 卷（kernel/rootfs/rootfs_data）
```

| 概念 | 说明 |
|---|---|
| MTD | 内存技术设备，屏蔽 NOR/NAND 差异 |
| UBI | NAND 的磨损均衡/坏块管理层 |
| UBIFS | 建立在 UBI 上的文件系统 |
| squashfs | 只读压缩根文件系统 |
| overlay | 可写层，通常是 jffs2/ubifs/ext4 |
| FIT | 把 kernel/DTB/rootfs 打包成一个镜像 |

## 3. OpenWrt 典型布局

```text
0x00000000  u-boot
0x00080000  u-boot-env
0x000c0000  factory         # MAC、无线校准、序列号
0x00100000  kernel
0x00500000  rootfs          # squashfs
0x...       rootfs_data     # overlay（首次启动创建）
```

NAND 设备常见 UBI 卷：

```text
ubi0: ubootenv
ubi0: ubootenv2
ubi0: kernel
ubi0: rootfs
ubi0: rootfs_data
```

> 具体偏移必须以 `/proc/mtd`、`dmesg`、DTS 和厂商分区表为准。

## 4. 升级与恢复的分区逻辑

| 操作 | 写哪里 | 保留什么 |
|---|---|---|
| `sysupgrade`（保留配置） | kernel + rootfs | `rootfs_data`/overlay、factory、uboot-env |
| `sysupgrade -n` | kernel + rootfs，清 overlay | factory、uboot-env |
| `firstboot` | 清空 overlay | 只读 rootfs |
| 恢复出厂 | 清 overlay + 重启 | 同上 |
| A/B 升级 | 写备用槽，切启动标志 | 当前槽可回滚 |

## 5. 常用命令

```bash
cat /proc/mtd
mtdinfo -a
ubinfo -a
ubimkvol /dev/ubi0 -N rootfs_data -m
blkid
df -h
mount | grep overlay

# 读写环境变量（需 /etc/fw_env.config 正确）
fw_printenv
fw_setenv bootcount 0

# 查看 UBI 卷
ubinfo /dev/ubi0
```

## 6. A/B 双分区（量产必备）

| 要点 | 说明 |
|---|---|
| 槽位 | A/B 各一套 kernel+rootfs |
| 启动标志 | U-Boot 读取 `bootcount`/`active_slot` |
| 失败回滚 | 启动失败 N 次后切回旧槽 |
| 数据分区 | 单独 data 分区，升级不动 |
| 版本校验 | 镜像元数据包含 board/version，防刷错 |

> OpenWrt 主线对 A/B 的支持因目标而异；自研产品通常需要改 U-Boot 与 sysupgrade 脚本。

## 7. 常见故障

| 现象 | 原因 | 排查 |
|---|---|---|
| 启动挂 rootfs | `root=` 分区名错、UBI 卷损坏 | `dmesg`、`ubinfo`、`mtdparts` |
| 升级后配置丢失 | overlay 被格式化 | 检查 sysupgrade 参数与分区 |
| 升级后无法启动 | 镜像与分区布局不匹配 | 串口日志、回滚 |
| MAC 变了 | factory 分区被覆盖 | 检查写入流程 |
| 无线校准丢失 | factory/art 分区被擦 | 从备份恢复 |
| NAND 坏块增多 | 频繁写、无磨损均衡 | `dmesg` 坏块信息、UBI 健康 |

## 8. 最小检查清单

- [ ] 升级前备份 factory、uboot-env、分区表。
- [ ] 确认 `sysupgrade` 镜像的 board 名与设备一致。
- [ ] 确认 overlay 分区存在且可写。
- [ ] 确认 A/B 槽位的启动标志与回滚策略。
- [ ] 确认产线写入 MAC/SN/校准数据的路径与校验。
