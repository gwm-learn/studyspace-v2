# 概率与排队论

> 解决什么问题：为什么“平均带宽够”但高峰期仍然卡；为什么队列越长时延越大；测试要跑多少样本才可信。
> 不解决：具体 QoS 配置（见 [QoS](../../8.数据面工程/04-QoS.md)）。

## 1. 随机变量与常用分布

| 分布 | 描述 | 网络中的典型场景 |
|---|---|---|
| 伯努利 | 一次试验成功/失败 | 单包丢失 |
| 二项 | n 次试验成功次数 | 一批包中的丢包数 |
| 泊松 | 单位时间到达次数 | 包到达、连接新建 |
| 指数 | 事件间隔 | 包间隔、会话时长 |
| 正态 | 连续测量误差 | 时延抖动、测试误差 |

关键统计量：

- 均值 `E[X]`：平均时延/平均丢包。
- 方差 `Var(X)`：抖动/稳定性。
- 分位数 `P99/P999`：尾时延，比均值更接近用户体验。
- 置信区间：样本均值 ± `z * σ/√n`。

> 工程上只看平均值会骗人：平均 20 ms、P99 500 ms 的网络，语音依然不可用。

## 2. 到达过程与突发性

- 泊松到达：`P(N(t)=k) = (λt)^k e^(-λt)/k!`，均值和方差都等于 `λt`。
- 真实流量往往**比泊松更突发**（自相似、长相关），泊松模型会低估排队。
- 突发度的工程度量：峰值/平均比（PAR）、突发长度、到达间隔的变异系数 `CV=σ/μ`。
- 测试时要用“真实业务剖面”，不要只用恒定速率 `iperf3 -b`。

## 3. 排队模型

### 3.1 记号（Kendall）

`A/S/c/K`：到达分布 / 服务分布 / 服务台数 / 系统容量。

常见：

- `M/M/1`：泊松到达、指数服务、单队列。
- `M/M/c`：多服务台。
- `M/G/1`：通用服务时间，能算平均等待（Pollaczek–Khinchine 公式）。

### 3.2 Little 定律

```text
L = λ W
```

- `L`：系统内平均包数。
- `λ`：到达率。
- `W`：平均停留时间。

用途：已知队列长度和到达率，可估算时延；反之亦然。

### 3.3 M/M/1 公式

设到达率 `λ`、服务率 `μ`、利用率 `ρ=λ/μ < 1`：

```text
平均系统内包数      L  = ρ / (1-ρ)
平均排队包数        Lq = ρ² / (1-ρ)
平均停留时间        W  = 1 / (μ-λ)
平均排队时间        Wq = ρ / (μ-λ)
空闲概率            P0 = 1-ρ
系统中恰有 n 个包   Pn = (1-ρ)ρ^n
```

数值例子：`λ=800 pps`、`μ=1000 pps`、`ρ=0.8`：

```text
Wq = 0.8 / (1000-800) = 0.004 s = 4 ms
Lq = 0.8² / 0.2 = 3.2 个包
```

当 `ρ=0.95`：`Wq = 0.95/(50) = 19 ms`；`ρ=0.99`：`99 ms`。**利用率接近 1 时时延非线性爆炸**。

### 3.4 为什么队列会“越排越长”

- 到达率短时超过服务率 → 队列积累。
- 队列长度有限 → 溢出丢包；无限 → 时延膨胀（bufferbloat）。
- 大缓冲并不等于好：它把“丢包”换成了“高时延”，对语音/游戏更糟。

## 4. 工程应用

### 4.1 带宽规划

- 按忙时 `P95` 流量规划，不按日均。
- 预留 `20–30%` 余量，避免 `ρ→1`。
- 上行往往比下行更容易拥塞（运营商侧整形）。

### 4.2 队列管理

| 机制 | 作用 |
|---|---|
| FIFO | 简单，易 bufferbloat |
| RED | 随机早丢，防全局同步 |
| CoDel | 基于排队时延，抗 bufferbloat |
| FQ-CoDel | 流公平 + CoDel |
| CAKE | 整形 + 公平 + AQM |

判定：满载时 `ping` 时延不应显著上升；若从 5 ms 涨到 300 ms，说明队列管理有问题。

### 4.3 测试采样

- 丢包率 `p` 的估计标准误：`sqrt(p(1-p)/n)`。
- 要区分 `0.1%` 与 `0.01%`，样本量要足够大（至少数万包）。
- 尾时延要跑足够长时间，覆盖突发。

## 5. 常见误区

| 误区 | 纠正 |
|---|---|
| 平均带宽够就不卡 | 看忙时/P95/队列 |
| 队列越大越好 | 大缓冲增加时延 |
| 丢包一定是链路差 | 可能队列溢出/整形 |
| 泊松模型万能 | 真实流量更突发 |
| 测 10 秒就下结论 | 样本不足，尾事件没覆盖 |

## 6. 实验

1. 用 `iperf3 -u -b` 逐步提高速率，观察丢包/时延。
2. 用 `tc qdisc` 加 `netem delay/loss`，验证应用表现。
3. 用 `ping -i 0.01` 在满载时测 P50/P99。
4. 记录 `tc -s qdisc` 的 backlog/drops。
