# 安全启动

> 解决什么问题：如何保证设备只运行"自己签过名"的固件，防止刷入/降级到恶意版本。
> 不解决：具体 SoC 的熔丝位与密钥注入产线细节（需厂商文档）。

## 1. 信任链

```text
BootROM（固化）
  │  校验（公钥哈希在 OTP/eFuse）
  ▼
BL2（TF-A）
  │  校验
  ▼
FIP（BL31 + U-Boot）
  │  校验
  ▼
kernel + DTB（FIT）
  │  校验
  ▼
rootfs（dm-verity / 签名）
```

每一级只信任上一级给的公钥/哈希；根在 OTP，不可改。

## 2. 关键机制

| 机制 | 说明 |
|---|---|
| 公钥哈希烧录 | OTP/eFuse 存根公钥哈希，掉电不丢 |
| 镜像签名 | RSA/ECDSA，签名覆盖 kernel/DTB/rootfs |
| FIT 签名 | U-Boot 的 `mkimage -F` 生成签名 FIT |
| dm-verity | 块级完整性，防 rootfs 篡改 |
| 防回滚 | 版本计数器，拒绝旧版本 |
| 调试锁定 | 关闭 JTAG/串口下载，防绕过 |

## 3. 签名与验证（FIT 示例）

```bash
# 生成签名 FIT（需要私钥与公钥）
mkimage -f image.its -k keys/ -r image.itb

# 查看签名信息
mkimage -l image.itb

# U-Boot 内验证
fit_check_sign -f image.itb -k public.key
```

`image.its` 关键节点：

```dts
signature-1 {
    algo = "sha256,rsa2048";
    key-name-hint = "prod";
    signed-images = "kernel", "fdt";
};
```

## 4. 密钥管理

| 项 | 要求 |
|---|---|
| 根密钥 | 离线、分片、多人保管 |
| 签名密钥 | HSM/安全服务器，权限最小化 |
| 开发密钥 | 与生产隔离，禁止流入量产 |
| 轮换 | 预留多把公钥/版本 |
| 吊销 | 防回滚 + 新版本 |
| 备份 | 离线多地，演练恢复 |

> 密钥丢失可能导致无法升级甚至变砖；必须有托管与恢复方案。

## 5. 生产流程

1. 产线注入根公钥哈希（OTP）。
2. 写入已签名固件。
3. 开启安全启动与调试锁定。
4. 回读校验（哈希/签名/版本）。
5. 记录到 MES（SN ↔ 密钥版本 ↔ 固件版本）。

## 6. 验证清单

- [ ] 未签名固件无法启动。
- [ ] 签名错误/被篡改的固件被拒绝。
- [ ] 旧版本（低于防回滚计数）被拒绝。
- [ ] 调试接口已锁定，无法绕过。
- [ ] 升级失败可回滚到已签名版本。
- [ ] 开发密钥未进入量产镜像。

## 7. 常见坑

| 坑 | 后果 |
|---|---|
| OTP 烧错 | 板子报废 |
| 只签 kernel 不签 rootfs | rootfs 可被替换 |
| 防回滚未做 | 可降级到漏洞版本 |
| 调试口未锁 | 可绕过安全启动 |
| 密钥无备份 | 无法升级 |
| 开发/生产密钥混用 | 供应链风险 |
