# 调试接口安全

> 解决什么问题：研发需要调试，量产必须关闭；如何平衡"可救砖"与"不可被接管"。
> 不解决：具体 SoC 的熔丝/寄存器操作。

## 1. 常见接口与风险

| 接口 | 能力 | 风险 | 量产建议 |
|---|---|---|---|
| UART | 控制台、U-Boot、shell | 直接拿 root/改启动 | 关闭或需认证 |
| JTAG/SWD | 内核/裸机调试 | 读写内存、绕过系统 | 熔丝锁定 |
| USB download | 刷机/救砖 | 刷入未签名固件 | 仅签名固件/关闭 |
| ADB | Android 调试 | shell/安装应用 | 关闭 |
| Telnet | 明文 shell | 嗅探/暴力 | 禁用 |
| SSH | 加密 shell | 弱口令/默认密钥 | 可选，限源 |
| Web | 管理面 | 弱口令/CSRF/XSS | 强认证 + HTTPS |
| 恢复模式 | 复位/救砖 | 物理接触即可 | 需按键组合 + 签名 |

## 2. 分层策略

| 阶段 | UART | JTAG | 刷机 | SSH/Telnet |
|---|---|---|---|---|
| 研发 | 开 | 开 | 开 | 开 |
| 试产 | 开（受控） | 开（受控） | 仅签名 | 受控 |
| 量产 | 关/只读 | 锁 | 仅签名 | 关/限源 |

## 3. 关闭方式（示例）

- U-Boot 环境：`silent=1`、关闭 `bootdelay`、限制 `run` 命令。
- 内核 cmdline：`console=` 指向空设备（谨慎，影响排障）。
- 文件系统：移除 `/etc/init.d/telnet`、`dropbear` 默认关闭。
- 熔丝：关闭 JTAG、开启安全启动。
- 物理：去掉测试点/排针，或加防拆。

> 关闭前必须保留**受控恢复路径**（签名固件 + 按键组合），否则售后无法救砖。

## 4. 恢复路径设计

| 方式 | 安全性 | 可救砖 | 说明 |
|---|---|---|---|
| 签名固件 + 按键恢复 | 高 | 是 | 推荐 |
| U-Boot TFTP（无签名） | 低 | 是 | 仅研发 |
| USB download（签名校验） | 中 | 是 | 需工具 |
| JTAG | 低 | 是 | 量产锁定 |

## 5. 检查清单

- [ ] 量产固件无默认 Telnet/ADB。
- [ ] SSH 默认关闭或仅 LAN/限源。
- [ ] UART 控制台关闭或需认证。
- [ ] JTAG 已锁定。
- [ ] 刷机只接受签名固件。
- [ ] 恢复模式需要物理按键组合。
- [ ] 日志不含密钥/口令。
- [ ] 售后有受控救砖流程。

## 6. 常见坑

| 坑 | 后果 |
|---|---|
| 只关 SSH，忘了 UART | 串口直接 root |
| 关闭 JTAG 但未锁 boot | 仍可刷未签名固件 |
| 恢复模式无签名校验 | 攻击者物理接触即可刷机 |
| 售后无救砖手段 | 返修率/成本上升 |
| 调试日志泄露密钥 | 供应链风险 |
